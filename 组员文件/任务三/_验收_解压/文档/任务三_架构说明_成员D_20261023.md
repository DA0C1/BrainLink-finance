# 任务三 · 架构说明

> 负责人：成员 D｜日期：2026-10-23

## 1. 总体结构

```text
浏览器（受试者 / 研究者）
        │  HTTPS / WebSocket（只收已发生数据）
        ▼
FastAPI（backend/main.py）
        │
        ├── SessionManager ── SessionRuntime（每会话一个）
        │        ├── PriceEngine / EventScheduler（服务端预生成）
        │        ├── Account（现金、持仓、盈亏）
        │        ├── Engine（MockEngine 或 state_engine 适配）
        │        └── 指标计算 metrics()
        │
        └── SessionStore（CSV + SQLite 双写、zip 导出）
```

前端为原生 HTML/CSS/ES Modules，无构建步骤；ECharts 5.5.1 本地存放于 `frontend/vendor/`，不依赖公网。

## 2. 一次 tick 的数据流

1. `_run()` 按服务端权威时钟 `start_epoch + tick × tick_ms` 对齐，逐 tick 调用 `_process_tick`。
2. 取 `price_engine.price_at(tick)`，写 `prices.csv` / SQLite。
3. 合成帧 → `engine.process_frame(frame, ctx={"task_active": True})` → `(Decision, Feedback)`。
4. 写 `states.csv`；向受试者推 `tick`（不含状态），向研究者推 `tick + state/conf`。
5. 若该 tick 命中事件表：落 `events.csv`，双方推送 `event`。
6. 若有反馈轮且反馈等级非 silent：落 `interventions.csv`，向受试者推 `feedback`（含状态与话术）。
7. 演示模式按固定脚本自动成交。

## 3. 防未来泄露设计

- 预生成不等于可读取：`PriceEngine` 只在服务端内存中持有完整序列，任何 HTTP/WS 序列化都从 `subject_snapshot()` 出发。
- `subject_snapshot()` 只构造 `0..current_tick` 的价格；事件只返回 `events_occurred`。
- 受试者 WS 的 `tick` 消息只有价格、涨跌幅、剩余秒数、状态；无 `state/conf/is_impulsive`。
- 无反馈轮不产生 `feedback` 消息，受试者端无法从消息流推断状态条件。
- 元数据接口只返回受试者编号、轮次序号、时长、模式，不返回 `seed/round/order`。
- 研究者端才接收状态、完整决策、干预与指标。

## 4. 三种模式

| 模式 | 触发 | tick | 时长 | 日志 | 界面 |
|---|---|---|---|---|---|
| experiment | 默认（tick≥2000ms） | 2000ms | 600s | 全量 | 正式界面 |
| test | tick<2000ms | 自定 | 自定 | 全量 | 顶部黄色水印 |
| demo | `POST /api/demo` | 2000ms | 180s | 不落 CSV | 顶部黄色横幅（自动成交） |

模式由 `SessionManager.create()` 根据 `demo` 与 `tick_ms` 判定，避免把加速模式误用于受试者。
演示模式与正式实验使用同一 2 秒/tick 节奏（缩短到 3 分钟），保证演示所见即受试者所见。
行情与 Mock 状态的时间窗口（如 30 秒追涨预热、25 秒事件状态、10 秒预热）按“秒”定义，运行时按 `tick_ms` 换算为 tick，保证不同节奏下时间含义一致。

## 5. 鉴权

- 研究者：HTTP 头 `X-Research-Token` 或查询参数 `token`，对比 `WATCHLAB_RESEARCH_TOKEN`。
- 受试者：加入会话时发放 32 位 token，后续 HTTP 与 WS 均校验。
- 会话码仅用于入场，不直接等价于受试者 token。

## 6. 数据模型

- SQLite：`sessions / decisions / events / states / prices / interventions`，供研究者端查询与列表。
- CSV：每会话一目录，UTF-8-SIG 带 BOM，Excel 直接打开不乱码。
- `decisions.csv` 固定 21 列，与全局 `DECISION_FIELDS` 一致；`engine_state / engine_conf / is_impulsive` 在成交瞬间从 `engine.last_decision` 快照。
- `session.json` 保存元数据与最终指标。

## 7. 时钟与随机源纪律

- 唯一时钟：`time.time()`；日期由 `time.strftime` 派生，不使用 `datetime`。
- 唯一随机源：`np.random.Generator(np.random.PCG64(seed))`，全项目不使用 `random` 模块。
- 同种子、同事件表下价格逐点一致（已实测两轮完全相同）。

## 8. 可替换点

- 真机接入：`SyntheticFrameSource` 替换为 SDK 回调帧，`StateEngineAdapter` 已按官方接口封装。
- 状态引擎：研究者建会话时选 `state_engine` 并给出 `engine_path`；默认自动尝试 `任务4_真机工具链\任务4_真机工具链`。
- 行情剧本：`config.py` 的段模板与事件概率可调，改动后需跑验收脚本。
