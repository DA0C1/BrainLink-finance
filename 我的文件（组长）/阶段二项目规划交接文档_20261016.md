## 三、任务明细（干什么、怎么做）

### T1 输出/提醒层设计（组长 E + 成员 B）
**现状**：引擎已产出 `Decision{state, conf, score, log}` + `Feedback{level: silent/mild/calm, message}` + `calmness=1−冲动率`，缺"送达用户"的形态。
**要做的**：
1. 成员 B 定交互形态：盯盘场景选**桌面角标/弹窗 + 可选语音播报**（calm 类话术如深呼吸适合播报；silent 类不打扰）；出交互稿（状态展示、提醒样式、理智度曲线）
2. 组长 E 接引擎：写 `output_demo.py`——mock 数据流（沿用 brain_sim_tb 覆写思路）喂引擎 → 屏幕实时刷新 8 状态切换、话术、理智度评分曲线
3. 预留真机接口：数据源替换为 SdkAdapter 即完成换源
**验收**：`output_demo.py` 可运行；演示 6 状态全对（focus 全程 conf=0.95 等）；理智度曲线随状态变化可见。

### T2 理智度验证方案（成员 C，组长审）
**要做的**：
1. 定义理智度指标（3 维，全部可由引擎 log 计算）：
   - 冲动率 / calmness（=1−冲动率，引擎已记录 impulsive/total）
   - 专注态占比（focus+flow 时间 / 总盯盘时间）
   - 干预响应率（提醒后 N 秒内状态是否改善，N 建议 30–60s）
2. 对照实验设计：**同一受试者 有反馈 vs 无反馈** 两轮模拟盯盘任务（自身对照，小样本 N=4–6 可行；顺序随机化防学习效应）；明确每轮时长（建议 10–15min）、数据采集字段
3. 输出任务范式需求清单（给 T3 的成员 D）：需要什么任务事件（价格波动、诱人追涨信号、突发消息）、如何打标
**验收**：指标口径可复算（有公式）；实验设计含对照、顺序、样本量；任务需求清单 T3 可直接实现。
**文献支撑**：成员 C 的 16 卡 + 组长综述（深呼吸干预有中国专家共识依据；专注态占比映射 θ/β 主口径）。

### T3 模拟交易任务范式（成员 D）
**要做的**（等 C 的指标与任务需求定稿后开始）：
1. 模拟盯盘界面/脚本：价格序列波动（可复现随机种子）+ 下单按钮 + 决策记录（时间戳/仓位/盈亏）
2. 干扰事件：诱人追涨信号、突发消息弹窗（按 C 的需求清单实现）
3. 与引擎对接：每帧把任务态注入 `ctx.task_active=True`，记录每笔决策时刻的引擎状态
**验收**：任务脚本可独立运行；决策日志含时间戳+引擎状态；有/无反馈两轮可切换。

### T4 真机联调工具链（成员 A）
**要做的**：
1. `serial_bridge.py`：读 BrainLink 串口 → 官方 `parser.parse()` → 回调进 SdkAdapter（接入代码模板已就绪，见 sdk_adapter.py 用法注释）
2. 数据录制器：真机数据存 CSV（EEG 频段/attention/meditation/HR/RR/gyro/signal/时间戳），供回放离线调参
3. 5 项验证测试模板（每项一个函数，真机到后逐项跑）：
   - V1 RR 间期质量（异常率/跳变/超生理范围占比）
   - V2 δ 额区可测性（清醒 vs 困倦功率可分性）
   - V3 signal 质量档位标定（定 `signal_min`）
   - V4 说话肌电（静默 vs 朗读 β/γ 变化，8× 门够不够）
   - V5 咖啡因对照（摄入前后 β/HR/RMSSD 变化）
**验收**：串口桥全链路通；录制 CSV 可回放进引擎；5 个测试函数有断言与输出。

### T5 答辩准备（组长 E + 成员 C）
**要做的**：
1. `答辩PPT大纲`：五段式——①阶段一文献（26 条+36 卡+M13 决议）②建模设计（θ/β 主口径、8 状态、判据-话术表）③验证路径（5 项真机清单+理智度实验）④现场演示（output_demo 走查）⑤边界与答辩要点（自首式标注：经验初值非文献、派生同步率非官方字段、F1 限定等）

## 六、阶段三入口（真机联调验证，交接给下一轮）

真机 BrainLink 寄到后执行。v1.1 采纳 5 点优化：验证顺序调整（signal 前置）、咖啡因降级可选、录制回放环节、通过标准+参数决策表、一次佩戴合并采集。

### 5.1 验证顺序（signal 前置，5 项）

```
V3 signal 标定 → V1 RR 质量 → V2 δ 可测性 → V4 说话肌电 → V5 咖啡因(可选/P2)
```

- **V3 前置理由**：signal 档位是数据可信度前提——佩戴后档位不稳定，RR 间期质量、δ 可测性都会失真；且 V3 最轻量（佩戴后读档位分布即可）
- **一次佩戴合并采集**：V3+V1+V2 可在同一段静息/睁眼采集同时记录（signal + RR + δ 三并行），减少佩戴次数（BrainLink 佩戴有学习成本）
- **V5 咖啡因**：降级为可选（伦理需被试同意 + 个体反应方差大）；属"现实干扰鲁棒性验证"（引擎在咖啡因下是否误判专注/压力），时间允许再测，或并入阶段 C 理智度实验作协变量

### 5.2 录制回放（离线验证环节，真机不在时也可调参）

1. 真机采集**原始数据落盘 CSV**（EEG 频段/attention/meditation/HR/RR/gyro/signal/时间戳，成员 A 的录制器）
2. 用 mock 回放跑引擎（CSV → SdkAdapter → 引擎），与在线联调解耦
3. 参数微调基于回放数据离线进行，避免反复佩戴；回放结果作为调参依据留痕

### 5.3 通过标准与参数决策映射表（验证结果 → 参数决策闭环）

| 验证项 | 通过标准（经验初值*，真机实测后确认） | 失败 → 参数决策 |
|---|---|---|
| V3 signal 标定 | 佩戴良好时稳定档位占比 >80% | 低档位数据丢弃策略（signal_min 收紧）；档位持续不稳 → 检查佩戴指导 |
| V1 RR 质量 | RR 丢失率 <10%、无连续伪值（<300ms/>2000ms 占比低） | 差 → RMSSD z 阈值放宽（Z_STRESS 保守化）或 HRV 窗加长；极差 → stress/focus 门控降级为佐证 |
| V2 δ 可测性 | 闭眼 vs 睁眼 δ 功率有区分度（z 可分） | 不可测 → drowsy 改单判据 TAR>+1.5（去掉 δ 合取，标注） |
| V4 说话肌电 | 说话时伪迹触发率 ≥90% | 不够 → 提高伪迹门 / 加"β+γ 同升且 θ 不动"肌电专用门 |
| V5 咖啡因(可选) | 摄入前后 β/HR/RMSSD 响应显著 | 不显著 → 兴奋态判据弱化标注；显著 → 应用层提示"摄入咖啡时段判据降权" |

*表中数值为经验初值，非文献值——真机数据到位后确认，答辩按自首式标注。
