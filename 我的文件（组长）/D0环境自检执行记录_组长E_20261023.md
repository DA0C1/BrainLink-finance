## 2 依赖安装（已完成）

```bash
py -m pip install --isolated --index-url https://pypi.org/simple pyserial
```

实测输出：`Successfully installed pyserial-3.5`

### 2.1 为什么必须带 `--isolated --index-url`

本机 pip 全局配置是：

```
global.index-url            = https://pypi.tuna.tsinghua.edu.cn/simple
global.extra-index-url      = https://mirrors.aliyun.com/pytorch-wheels/cu128
```

**清华源在当前网络下不可达**，且报错具有极强误导性：

```
ERROR: Could not find a version that satisfies the requirement pyserial (from versions: none)
ERROR: No matching distribution found for pyserial
```

看起来像"包名写错/包不存在"，实际是**源连不上**。`extra-index-url` 指向的阿里云 pytorch 镜像同样会拖慢失败。
`--isolated` 让 pip 忽略全部配置文件，避免这两个源参与解析。

> **判据**：真正的"包不存在"（如下面的 BrainLinkParser）用官方源也会报 `from versions: none`；
> 而源不通时换成官方源立刻能装。**同样的报错文案，原因完全不同**——所以第一次失败别急着改包名。

### 2.2 `BrainLinkParser` 的最终结论：**不可装，不必再试**

```bash
py -m pip download --no-deps --isolated --index-url https://pypi.org/simple BrainLinkParser
# ERROR: Could not find a version that satisfies the requirement BrainLinkParser (from versions: none)
```

用**官方源**仍 `from versions: none` → **它根本不在 PyPI**，只能从 GitHub 手动装，且官方 README 标注 Python 3.11。

结论：**放弃官方 pyd，确定走 `项目文件/tgam_parser.py`（纯 Python）**。
D0 §1.0 里"两条路径待验证"到此收敛为一条，无需再找 zip、无需装 3.11 便携版。

代价已在 `纯Python自解析可行性评估_组长E_20261023.md` 量化：**8 态仅 `stress` 不可判**，其余 7 态正常。

## 4 本轮新发现并修复：串口"静默失败"无告警（现场级）

### 4.1 现象

本机 `list_ports` 枚举出 **COM1（主板自带通信端口）**。用 COM1 直接启动：

```
[bridge] 解析器：纯 Python tgam_parser（...）
[bridge] 串口 COM1@115200 已打开；Ctrl+C 结束（录制：关闭）
（然后 10 秒内零输出、零字节、零报错）
```

**串口打开成功 ≠ 有数据**。原实现只在 `serial.Serial()` 抛异常时才提示，
于是"打开了但设备不说话"的场景**完全静默**——现场极容易误判为"正在采集"，直到事后发现 CSV 是空表。

这与本项目此前两处问题同源（RMSSD 恒 nan 仍 PASS、`signal=230` 超范围仍 PASS）：
**工具无法区分"连上了"与"收到数据了"**。

### 4.2 修复

`serial_bridge.py` / `live_bridge.py` 均加入**静默看门狗**：串口打开后 15s 内累计接收 0 字节 → 主动告警并给出排查顺序；一旦收到数据自动停报。

实测触发效果（COM1，故意静默）：

```
[bridge] [警告] 已 15s 未收到任何字节（COM1）——串口开着，但设备没在发数据。
  ① 最可能：选到了「传入」口或主板自带口（如 COM1）→ 换另一个 COM 口试
  ② 其次：头环被手机 App 占用 → 关 App / 清后台
  ③ 再则：头环已休眠 → 按电源键唤醒
  （采集未中断；一旦收到数据会自动停报）
```

### 4.3 回归确认（修改后）

`py_compile` 通过；`v26/v28/v29/v30/parity` 五项 exit=0；`--mock` 仍 **7 条 OK**；`--demo` 仍 **正例 5/5**；`verify_tgam` 仍通过。

### 4.4 现场含义

COM 口从"两个"变成**至少三个候选**（BrainLink 传入 + 传出 + 主板 COM1）。
选错的三种表现现在都有对照：

| 你看到的 | 含义 | 处置 |
|---|---|---|
| `串口打开失败 ... FileNotFoundError` | COM 号不存在/未配对 | 查设备管理器实际编号 |
| `已打开` + 15s 后 `[警告] 未收到任何字节` | **口选错了**或设备没开机 | 换另一个 COM；确认头环已唤醒 |
| `已收到数据（累计 N 字节），通道正常` | 链路通了 | 继续 D1 |
