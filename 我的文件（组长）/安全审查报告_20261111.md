## 3. 详细发现

### 3.1 Host 头未校验 → DNS rebinding 可读取实时生理数据（中危，已修复）

- **位置**：`项目文件/live_bridge.py` → `Handler.do_GET` / `do_HEAD`
- **类型**：认证绕过 / 数据泄露（CWE-350 依赖不可信来源做安全决策）
- **描述**：服务只绑定 `127.0.0.1`，但**不校验 `Host` 头**。任何请求都按正常处理：

  ```
  $ curl -H "Host: evil.example.com" http://127.0.0.1:8792/health
  {"ok": true, "source": "mock", "frames": 9, "clients": 0, "uptime": 2.8}   ← 200

  $ curl -H "Host: evil.example.com" http://127.0.0.1:8792/
  HTTP 200
  ```

- **影响**：攻击者页面 `evil.com`（TTL=0）先解析到自己的 IP，再切到 `127.0.0.1`；浏览器判定为**同源**，于是可以 `fetch('/health')` 并 `new EventSource('/stream')` 持续读取 EEG 频段、注意力/冥想度、心率等生理数据。对 BCI 产品，泄露的不只是页面，是受试者的实时生理状态。
- **置信度**：确认（已用 curl 复现 200）
- **建议修复**：只接受白名单 Host；缺失 Host 直接拒（HTTP/1.1 必需字段）。局域网场景用 `--allow-host` 显式放行。

  ```python
  LOOPBACK_HOSTS = {"127.0.0.1", "localhost", "[::1]", "::1"}

  @staticmethod
  def _host_name(host: str) -> str:
      host = (host or "").strip().lower()
      if host.startswith("["):
          return host.split("]")[0] + "]"
      return host.rsplit(":", 1)[0] if ":" in host else host

  def _host_ok(self) -> bool:
      raw = self.headers.get("Host")
      return bool(raw) and self._host_name(raw) in self.allowed_hosts
  ```

  验证结果：合法 Host 200 / `localhost` 200 / `evil.example.com` **403** / `--allow-host mypc.local` 200 / 无 Host **403**。

### 3.2 SSE 无客户端上限 → 线程耗尽（中危，已修复）

- **位置**：`项目文件/live_bridge.py` → `Handler._stream`
- **类型**：资源耗尽（CWE-770 无限制分配资源）
- **描述**：`ThreadingHTTPServer` 每个 SSE 连接占一个线程且长期存活，`_stream` 无上限判断。配合 3.1，一个恶意页面可批量开 `EventSource` 把面板拖到无响应。
- **影响**：本机 DoS；演示现场"界面卡死"但服务进程仍在。
- **置信度**：确认（实测 18 条并发连接全部 `200`，无任何限制）
- **建议修复**：上限 16，且**必须在写响应头之前判**（写完之后再返回 503 无效——响应行已是 200）。

  ```python
  MAX_SSE_CLIENTS = 16

  def _stream(self) -> None:
      if self.broker.clients >= MAX_SSE_CLIENTS:      # 先判，再发头
          self.close_connection = True
          self._text(503, f"too many clients（上限 {MAX_SSE_CLIENTS}）")
          return
      self.send_response(200)
      ...
  ```

  验证结果：18 条并发 → `200×16 + 503×2`。

### 3.3 `--host 0.0.0.0` 时无鉴权（低危，接受并文档化）

- **位置**：`项目文件/live_bridge.py:546` `--host` 参数
- **类型**：缺失访问控制（CWE-306）
- **描述**：默认 `127.0.0.1` 时风险可接受；一旦显式 `--host 0.0.0.0`，同网段任何人都能读 `/stream` 与 `/health`，无任何凭据校验。
- **影响**：局域网内的生理数据泄露（实验室/办公室网络属"半可信"环境）。
- **置信度**：确认（设计取舍，非缺陷）
- **建议修复**：保持"默认不暴露"；`--host` 非回环时**启动即打印醒目告警**并列出允许的 Host（已实现）。若确需跨机演示，建议走 SSH 隧道或在前面加一层 Nginx Basic Auth，不在应用内自建账号体系。

- **位置**：`项目文件/live_bridge.py` `_json({"source": self.broker.source, ...})`

- **描述**：`source` 形如 `replay:d2c38.csv`（回放时带文件名）、`serial:signal=30`（串口时带接触值）。
- **影响**：泄露本机文件名/接触质量，不含受试者身份信息。
- **置信度**：确认
- **建议修复**：可接受（本机诊断需要）。若未来对外暴露，把 `source` 收敛为枚举值（`mock/serial/replay`），细节留在日志。
