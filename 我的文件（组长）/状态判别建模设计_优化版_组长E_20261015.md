## 二、总体架构（数据流）

```
原始帧(1.2–1.5s)
 → ① 信号质量门 + 伪迹剔除（EEG: 比值>8×平滑 / 体动门; HR: RR 生理范围+运动回归）
 → ② 平滑（EEG: EWMA α=0.2; HR/RMSSD: 60s 滑动窗）
 → ③ 特征计算（EEG 10s 窗均值; HRV 60s 窗; 速率 30s 差分; 疲劳积分; 体动能量）
 → ④ z-score 个体偏离（基线 μ/σ，滚动慢速更新）
 → ⑤ 状态评分（线性加权：分=Σ wᵢ·zᵢ）→ 状态仲裁（优先级+窗口命中率+防抖）→ 置信度
 → ⑥ 反馈策略（状态机 + 冷却 + 干预动作）→ ⑦ 理智度记录（含 A/B 对照）
```

**设计变更 vs 原方案**：
1. 绝对比例阈值（0.85/1.15、+8bpm、−30%）→ **z-score 个体偏离**（R6/R7 实证）
2. 单帧 AND 硬规则 → **加权评分 + 窗口命中率**（R2/R5 验证）
3. 漏嗜睡 → **补嗜睡状态**（R8 现成公式 + 映射表 M5）
4. 静态基线 → **校准+慢速自适应滚动基线**（R3/R4/R9）
5. 未用陀螺仪 → **体动能量进特征 + EEG 伪迹门**（R5 运动回归思想）
6. 过度兴奋"突发后平台"无算法 → **z(β)+z(HR) 联合门控**（v2.2：区分核心=心率，见 §三）

def feature_extract(window) -> dict
    输入: 10s EEG 窗 + 60s RR 窗 + 30s GYRO 窗
    输出:
      R_tb   = mean(θ)/mean(β)                     # 专注主口径（M13）
      R_ba   = mean(β)/[mean(θ)+mean(α)]            # Engagement 指数（Pope/R2）
      TAR    = mean(θ)/mean(α)                      # 嗜睡（R8）
      BAR    = mean(β)/mean(α)                      # 警觉（R8）
      A_rel  = (ᾱ − α_baseline)/α_baseline         # α 相对偏离
            # v2.2 口径澄清：α_baseline = 主任务前睁眼基线（校准 B 段末尾或任务开始前 30s）

def state_arbitrate(scores, gates, priority, cfg, ctx) -> (state, conf)
    1. 时间确认统一（v2.7 实装，§四）：DEBOUNCE_S=5s 滑动窗内命中率 ≥HIT_RATIO(0.6)
       才确认候选状态，未达输出 neutral；neutral 帧不进入命中缓冲（不稀释候选确认）
       # 旧"慢变 60s/快变 5s 分轨"已被统一 5s 窗替代（v2.8.2 文档对齐）
    2. 优先级仲裁（同窗多状态命中，v2.8 八状态）：
       stress > anxiety > drowsy > fatigue > distracted > flow > focus > relaxed
       # 门控定资格、优先级定胜负（分数只用于 conf）；drowsy 在 fatigue 前
       # （嗜睡帧 TAR 高必然 R_tb 高，否则被 distracted 抢占）
    3. 置信度 conf（v3.4 改口径：比**同量纲的证据**；v3.4.1 补上绝对强度维度）
       每状态先算门控余量 m（σ 当量；合取取 min、析取取 max），再归一成证据 e = clamp(m/EVID_REF, 0, 1)
       conf = CONF_MIN + (CONF_MAX−CONF_MIN) · sep · strength
         sep      = e_best / (e_best + e_second)          # 排他性：与竞争对手差多远
         strength = clamp(m_best / EVID_FULL, 0, 1)       # 绝对强度：本身离阈值多远
       # 旧式 0.6 + 0.35·(score_max − score_2nd)/(|score_max|+|score_2nd|+ε) 比的是**不同量纲的分数**：
       #   z 组合量级 1–3，官方指数余量量级 10–20 → "RMSSD z=−2 的强应激(2.0) 与 att/med=30 的焦虑(20) 并存"
       #   场景下 conf 被压到下限 0.60，强应激被标"弱判别仅记录"，干预永不触发；改证据比后 0.60→0.75。
       # v3.4 只做 sep 时有个更老的洞（旧式也有，只是被跨量纲问题掩盖）：**单候选时 sep 恒 1** →
       #   超阈 0.001σ 与超阈 5σ 都给 0.95，WEAK_CONF（弱判别仅记录）永不生效。加 strength 后：
       #   余量 0.001σ → 0.601（弱判别）、0.25σ → 0.775、≥0.5σ → 0.95（verify_engine E7 端到端锁死）。
       # EVID_REF=1σ 服务 sep（要区分度），EVID_FULL=0.5σ 服务 strength（"够硬"的门槛），
       #   两者分工不同、不可合并。实测典型命中余量中位 2.0σ、P25≈0.9σ，取 0.5σ 属保守。
       # Decision 同时返回 margins（强度）与 evidence（证据）——"强应激但因焦虑并存 conf 中等"由此可解释。
       # 仲裁仍**只按优先级**（临床语义），conf 不参与选状态。

       # 输出前 clamp 至 [0.6, 0.95]

### 6.2 v3.1 修正：θ_ref 必须取 B 段（本轮最重要的设计修正）

**现象**：模拟真机校准（A 段闭眼 θ≈100–130、B 段睁眼任务 θ≈55–100）后，主任务 θ=82.5 时
`θ_norm = 82.5/130 = 0.63 < IF_THETA_NORM(1.2)` → `I_f` 恒 0 → **疲劳永远判不出来**。
若 θ_ref 取 B 段（55）则 `θ_norm=1.50`、`I_f` 正常累积，能判出 fatigue。

**根因**：A 段闭眼 θ 系统性高于睁眼任务；且 R_tb/R_ba/TAR/A_rel/HR/RMSSD/still **全部以 B 段为参照**，
唯独 θ_ref 用 A 段——**参照系不一致**。这不是阈值问题，拿阈值调是治不好的。

**处置**：θ_ref 改取 B 段中位数，A 段 θ 另存 `theta_rest` 只作展示；
`verify_v28` V13 断言方向随之反转（原测试把错误口径写死成"期望"）；
`verify_v30` 新增 I 用例锁死"校准后疲劳可达"；`verify_parity` 新增**闸门 3**（两侧基线逐项比对），
防止这类"常量相同、轨迹相同、基线不同"的分叉再次悄悄发生。

### 6.3 v3.1 新增：β+γ 肌电专用门（默认关闭）

**为什么需要**：比值型伪迹门是**突变检测**。对**渐变起音**的持续肌电（说话、咬牙由轻到重），
每一帧相对参照都不到门限，参照一路跟着涨 → 伪迹率上不去 → 朗读段 EEG 被当有效数据（β 升 → 误判 stress/anxiety）。
`verify_hw.py V4` 实测：朗读段单频段门拦截率 **0%**。

> v3.4 补充（结论要分清）：参照系换成中位数后，**突变型**持续伪迹已能全拦（`_audit_engine` A7：β 一步到 20×
> → 40/40）；但**渐变起音**（每帧 +7.8%，40 帧升到 20×）两版都拦不住（0/40）——比值判据分不清
> "缓慢涨 20 倍"与"真实状态迁移"。所以本节的 β+γ 专用门**仍需要**，针对的正是渐变形。

**判据**：`β > 4×beta_ref` 且 `γ > 4×gamma_ref` 且 `|θ − theta_ref| < 0.35×theta_ref`。
取 4× 而非 2×：真实肌电幅值远超 EEG（10–100×），2× 会与"认知负荷升 β"混淆；
θ 限定是为了不把真实状态迁移（θ 真的大动）当肌电拦掉。

**开关**：`ARTIFACT_EMG_GATE`（Python 与 JS 各一处，**必须同时改**，否则 parity 闸门 1 会红）。
默认为 `False`——是否启用由真机 V4 结果决定，不拿合成数据替真机做决定。


### 6.4 v3.4 校准口径修正（三处 + 伪迹剔除，P3-3 在此闭合）

**① δ 基线必须取 B 段**（与 6.2 的 θ_ref 属同一失效模式，只是换了个特征重新引入）

旧实现只从 A 段取 δ（闭眼静息，δ 系统性偏高，实测 μ=149.7），而判别发生在睁眼任务（δ≈100–120）：
任务中 δ=118 时 `z(δ)=(118−149.7)/6.8 = −3.42` → 嗜睡门控要求 `z(δ)>+1.0` → **永久不成立**，
真机校准后嗜睡静默失效。改取 B 段后 μ=104.0、**z=+2.05**（`verify_engine` E9；`_audit_engine` A2 可复现）。
A 段 δ 保留为 `delta_rest` 仅作参考。

**② RMSSD 校准与运行时同口径（遗留 P3-3）**

旧实现按"帧→帧"差分，运行时按"批内差分"（真机一次 onRR 三值是连续心跳，跨回调可能隔着丢帧/重叠）——
同一段 RR 数据能差出 40%+ 的差分对数，掉搏时量级都不同。实测基线偏差 **−89.2%**（校准虚低 → z 偏高 → 压力少报）。
现统一走 `RmssdWindow`（同一函数、同一批次语义、同一异位滤波），三种数据形态偏差 **0.0%**
（`verify_engine` E10：运行 10.4658ms == 校准 10.4658ms，逐位相等；`_audit_engine` A3）。

**③ α 基线先算、A_rel 再算（显式两段）**

旧实现依赖特征名列表的迭代顺序：`A_rel` 恰好在 `alpha` 之前被算时，会静默用**默认 α=100** 折算 →
放松判据整体偏移。现显式两段，`verify_engine` E11 断言"改 α 基线 ⇒ A_rel 随之变"（C 段 z=+5.30）。

**④ 统计前剔除伪迹/接触无效帧**

旧实现直接统计原始帧：40% 眨眼段把 σ 从 5 抬到 586（`verify_engine` E13），z 判据被压扁。
现走运行同一个 `ArtifactDetector`，同一段数据 σ=5.0、μ=109.5，并且校准报告**报出**"伪迹率 40% > 30%"。

**双引擎契约**：以上四条两侧逐值一致——`verify_parity` 闸门 3 已从"5 个标量"扩到 **18 项**
（θ_ref 来源 / α·δ·A_rel·R_tb·RMSSD 的 μ 与 σ / 伪迹率 / 差分对），两侧任何一处口径分叉都会红。

## 七、实施路径与验证

1. **模拟验证**（当前）：brain_sim.py + brain_sim_tb.py 管道跑通特征→评分→仲裁→反馈全链路；随机游走数据**只验证管道与格式**，不验证判别准确性（明示）。
2. **真机验证**：采集 3 个诱发状态（专注任务/TSST 式压力/闭眼放松）各 2min → 检查判别状态与诱发状态一致性；调 z 阈值。
3. **理智度 A/B**：无干预 vs 有干预任务段比较冲动率（冷静度）与回落率（干预有效率）。
   - v2.1 修正：固定"先无后有"存在**顺序效应**（疲劳/学习累积会污染结论）——改用 **A/B/A 交叉**（干预-无干预-干预，或随机交替），配对比较；
   - 样本≥5 且干预段有效率 > 自然回落率才给"趋势提示"结论，小样本不宣称因果。
4. **答辩口径**：所有 z 阈值/权重标注"文献方向 + 个体校准初值，真机拟合中"，不宣称已定标。
   - v2.3 补充：F1=89% 必须带"EPOCX 14 通道被试内"限定（单通道额区不可复现）；R6 标注工作坊预印本、R8 标注工程化公式非官方、R10 标注低权威来源——被问到的三处自首，主动说明比被追问更稳。

## 八、遗留与风险

- 模拟数据不验证准确性（已明示，答辩主动说明）
- z 阈值初值缺大规模实证（R6 的 −1.5σ 是 HRV 应激，EEG 各状态需真机校准）
- 消费级 HRV 精度：RMSSD 时域抗噪较好，但体动影响大——靠 still 特征+运动回归门控缓解（R5）
- 嗜睡判别在短时演示中可能样本不足——作为"状态覆盖完整性"答辩点展示，不硬造结论
- **渐变起音的持续肌电两版都拦不住**（每帧 +7.8%、40 帧升到 20× → 拦截 0/40）：比值判据分不清
  "缓慢涨 20 倍"与"真实状态迁移"。处置：β+γ 专用门（§6.3，默认关），真机 V4 判是否启用；
  这是**已知局限**，不宣称已被 v3.4 解决。
- **伪迹参照系有逃生门副作用**：连续 60 帧（≈1 分钟）全判伪迹时重建参照，意味着"持续 1 分钟的真伪迹"
  会被当作"电平变了"重新接收（计入 `reseeds` 诊断）。取舍理由：锁死的代价（永久判不出状态）更大。
- **遗留 P3-3（校准/运行 RMSSD 口径不统一）已在代码层闭合**（§6.4②，偏差 −89.2%→0.0%），
  但仍需真机数据复核：合成数据上逐位相等，不等于真机 RR 序列（含丢帧/重叠）也相等。
- **验证脚本本身也可能骗人**（v3.4.1 教训）：`_diff_*` 的 att/med 插值 bug 让 anxiety 段空跑，
  而闸门 2 一直绿。凡"逐段一致"类断言，必须同时断言**每段都命中了目标状态**，
  否则一致的是"两侧都没判出来"。这条已写进闸门 2 的验收口径（8 段状态逐段核对）。
- **conf 的数值口径在 v3.4.1 收紧**：叠加 strength 后，"刚过门控"不再给高置信度。
  历史脚本里凡按 `conf ≥ 0.95` 做断言的（如 `output_demo` 的 relaxed 段）都要用**余量**而非旧 conf 复核，
  否则会把"正常收紧"误读成"退化"。真机上需重标 `EVID_REF` / `EVID_FULL` 两个常量。

### v3.6（第二十轮：真机首采数据到位 → 抓到采集驱动致命缺陷 + 打包泄漏，2026-11-09 晚）

> 触发：收到首份真机 dump `real_sub01_20261109_211433.jsonl`（247 行 / 69.9 KB / 241 EEG 帧）。
> 本来只想跑一遍分析，结果**数据本身先暴露了四个问题**，一个比一个严重。

#### 一、致命：校准 6 分 30 秒一帧未采（采集脚本单线程阻塞）

数据形态（不是推断，是 dump 里量出来的）：

```
marker   t =   8417 … 401156 ms      D2_A / _END / B / _END / C / _END 六条齐全
全部 eeg t = 401157 … 639285 ms      seq 6–246 连续无缺号，1 Hz
```

即：**三段校准期间零帧，D2_C_END 那一刻起突然恢复正常 1 Hz**。`wall` 与 `t` 完全自洽，
所以不是时间戳错误，是真的没收。

根因在 `collect_real.py::run_live`：

```python
ser = serial.Serial(port, baud, timeout=1.0)
guided_session(dump, preset, sim=False)   # ← 全程 input() 阻塞，没人读串口
while True:                               # ← 分段结束后才开始读
    chunk = ser.read(4096)
```

Windows 蓝牙 SPP 驱动缓冲很小，不读就丢。**这不是硬件问题，是脚本自己把校准段扔了。**

修法：`ser.read()` 移入独立线程（daemon），主线程只负责 `input()`；静默看门狗一并移入。
另加两道现场门禁：
- **首帧门禁**：20 s 内无帧 → 明示三条现场原因（传出 COM / App 占用 / 休眠），默认中止
- **段自证**：每段结束打印本段实际帧数，零帧当场红字告警（旧版毫无反馈，回家才发现）

**反证**（`verify_collect.py`，5 组 12 项断言）：假串口 + 假 `input`（每次阻塞 0.3 s），
断言三段各 6 帧、合计 44 帧。**旧版在这套断言下必然是 0**，所以它真能抓住该缺陷。

#### 二、回放不确定：同一份 dump 连跑三次三个答案

| 次数 | 状态分布 |
|---|---|
| 1 | drowsy×117, neutral×105, relaxed×18 |
| 2 | drowsy×121, neutral×101, relaxed×18 |
| 3 | drowsy×120, neutral×102, relaxed×18 |

根因：`analyze_real.py::py_frame` 与 `SdkAdapter.onEEG` 都不给 `Frame.ts`，
引擎回退 `self._clock()`（wall-clock）。真机链路里这没问题（帧到达即真实时刻），
但**离线回放把 4 分钟数据瞬间灌入**，`dt≈0` → 疲劳积分 I_f 的衰减完全不成立。

修法：`onEEG` 增加 `ts=getattr(data,"ts",None)`（纯增量，数据不带 ts 时行为不变）；
