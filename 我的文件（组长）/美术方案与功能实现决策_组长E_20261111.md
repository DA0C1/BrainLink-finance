# 界面美术方案与功能实现决策（v3.10）

> 组长 E · 2026-11-11
> 依据：`ui-ux-pro-max` 设计引擎（UX-002 对比度 / UX-005 焦点 / UX-012 触控目标）
> 　　+ 本项目既有语义（**红色 = 告警**）+ 便携包**离线运行**的硬约束

---

## 一、约束条件（先定边界，再谈方案）

| 约束 | 来源 | 对设计的直接影响 |
|---|---|---|
| 便携包离线运行，不联网 | `打包便携版.py` | **不能引入 Web Font**（Google Fonts 链接在离线机上是死链），只能用 system-ui 栈 |
| 红色专用于告警/危险 | 既有 8 态语义（alert 级别、伪迹、超限） | 主色不能用红；"暂停"这类常规操作也不能染红 |
| 单页三栏，主战场 1440×900 | 现场投屏 | 三栏结构不能动；超宽要限宽，矮屏要能滚 |
| 中文字体优先 | 受试者/评委均为中文用户 | 字号偏小一档（汉字比拉丁字母视觉更重） |
| 已有 14 项对比度实测通过 | `_a11y.mjs` | 不动调色板，只补语义与层级 |

## 二、技术决策（含放弃的方案）

| # | 决策 | 选择 | 理由 | 放弃的方案 |
|---|---|---|---|---|
| 1 | 色彩 | **保留**现有语义 token（`--good/--warn/--alert/--brand`） | 已实测 14/14 达标；改主色会破坏"红=告警"这一跨文档约定 | 设计引擎推荐的暗红主色 `#A74444` —— 与告警语义直接冲突 |
| 2 | 字号 | **8 档令牌**：10.5 / 11.5 / 12.5 / 14 / 15 / 18 / 22 / 30 | 原 17 档里相邻差 <1px 的占一半，肉眼无区别，只是维护负担 | ① 完整模块化音阶（12/14/16/20/24…）会整体改变观感，答辩前风险高；② 全站 `rem` 化需重算 300+ 处 |
| 3 | 圆角 | **5 档**：4 / 10 / 12 / 16 / 999 | 2–7px 在 1× 屏上等价于 4；8–11 等价于 10 | 全站统一 8px —— 会抹掉"卡片 > 按钮 > 徽标"的层次 |
| 4 | 间距 | **只在新组件用 4px 倍数**，不全局替换 | 全站改间距 = 重新排版，收益在维护性而非当下观感 | 4px 栅格全量替换（会影响 40+ 组 padding/margin） |
| 5 | 布局 | 桌面三栏 + **1680 限宽居中**；≤1280 宽 / ≤780 高 转内容流滚动 | 实测 1920 拉成 2.5:1 的扁图、1366×650 卡片压页脚 | `auto-fit` 自适应列数 —— 会打乱"状态/曲线/提醒"的三栏语义 |
| 6 | 字体 | system-ui → PingFang SC / 微软雅黑 | 离线可用，零加载成本 | Inter / Space Grotesk（引擎推荐）—— 便携包离线不可用 |
| 7 | 动效 | 保留 0.16–0.35s 过渡，新增元素统一 `prefers-reduced-motion` 关断 | 已有全局降级规则 | 引入入场编排 —— 仪表盘高频刷新，动效越多越吵 |

## 三、令牌表（已落地于 `css/styles.css :root`）

```css
/* 字号：17 档 → 8 档 */
--fs-micro: 10.5px;   /* 角标 / 极微标签（29 处） */
--fs-cap: 11.5px;     /* 说明 / hint（24 处） */
--fs-body: 12.5px;    /* 正文 / 按钮（24 处） */
--fs-num: 14px;       /* 指标值 / 卡片标题（14 处） */
--fs-sec: 15px;       /* 小节标题（3 处） */
--fs-hero: 18px;      /* 状态名（6 处） */
--fs-icon: 22px;      /* 空态图标（1 处） */
--fs-display: 30px;   /* 主数值（2 处） */

/* 圆角：13 档 → 5 档 */
--r-xs: 4px;      /* 徽标 / 进度条 */
--r-sm: 10px;     /* 按钮 / 指标格 / 输入 */
--r-md: 12px;     /* 中等容器 */
--r-lg: 16px;     /* 卡片 */
--r-pill: 999px;  /* 胶囊 / 开关 */
```

替换后**零残留字面量**（脚本校验：`font-size: Npx` 0 处、`border-radius: Npx` 0 处）。

## 四、组件规范（新增/修改时按此写）

| 组件 | 规则 |
|---|---|
| 按钮 | 三级：`primary-btn`（品牌渐变，仅"开始"）/ `ghost-btn`（描边，次级）/ `icon-btn`（顶栏）。统一 `--r-sm`，`:focus-visible` 2px 品牌描边，禁用 `opacity:.5` |
| 卡片 | `--surface` + 1px `--border` + `--r-lg` + `shadow-1`；`.card-head` 用 `--fs-num` 粗体；`.card-foot` 用 `margin-top:auto` 贴底 |
| 指标格 | `--surface-2` + `--r-sm`；标签 `--fs-micro`、值 `--fs-num` 粗体 + `tabular-nums`；接触质量按 `data-q` 着色（good/warn/alert） |
| 状态格 | 默认 `--surface-2`；`.active` 品牌描边 + 2px 外环；`[injected]` 右上角标（仅 auto/manual 模式出现） |
| 空态 | 图标 `--fs-icon`（灰度）+ 标题 `--fs-body` + 说明 `--fs-micro`，列表区内**透明底** |
| 提示条 | 整行、左侧 3px 色条；`warn`（黄）/`alert`（红）两档；必须带可执行动作（如"重新连接"） |
| 诊断块 | 状态点 9px + 一句结论 + 四个读数；点在 `ok`/`err` 时加 3px 光晕（不靠颜色单独表意，同时改文案） |

## 五、功能实现方案（本轮落地）

### 5.1 数据源诊断（补上前端唯一"看不见后端"的盲区）

| 项 | 内容 |
|---|---|
| 问题 | `/health` 从 v2.9 就存在，但前端从未调用 —— 现场判断"服务是否活着/有没有人在看/推了多少帧"只能另开终端 curl |
| 方案 | 设置面板顶部新增「数据源诊断」：`fetch('/health')` → 状态点 + 结论 + 4 个读数（数据源/已推送/SSE 连接/运行时长） |
| 交互 | 打开设置面板自动查一次；「刷新诊断」手动重查；2.5s 超时；失败时**说清原因**并给出排查方向 |
| 代码 | `app.js` `refreshDiag()` / `setDiag()` / `fmtUptime()`；`index.html` `#diagBox`；`styles.css` `.diag` |

### 5.2 校准时间戳

| 项 | 内容 |
|---|---|
| 问题 | `calibMeta.at` 从 v3.6 就在存，但界面从未读取 —— 现场分不清"刚校的"和"三天前的" |
| 方案 | 校准面板摘要增加「上次校准」：`11-11 13:02 · 1 小时前`；未校准显示「未校准」；旧数据无时间戳显示「未知（旧版保存）」 |
| 一致性 | 导入基线也写时间戳；恢复默认时清空（否则会显示上一份的时间） |

### 5.3 安全加固（详见《安全审查报告_20261111》）

- Host 白名单（防 DNS rebinding，实测伪造 Host 由 200 → 403）
- SSE 客户端上限 16（超限 503，实测 16×200 + 2×503）

## 六、未做项与原因

| 项 | 为什么不做 |
|---|---|
| 全站 4px 间距栅格 | 需重排 40+ 组间距，收益在维护性；本周重点是答辩 |
| 深色下 emoji 去色 | 状态格的 emoji 是语义色（😴嗜睡/😰压力），去色会丢信息 |
| Web Font | 便携包离线，加载必然失败 |
| 提醒筛选 chip 中文化 | `mild/calm/silent` 是贯穿文档与代码的档位名，改中文会造成两处维护 |
