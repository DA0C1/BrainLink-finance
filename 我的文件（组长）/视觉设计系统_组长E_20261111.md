## 一、设计目标与适用范围

### 1.1 这套界面要解决什么

给**盯盘场景下的受试者/研究员**看实时脑状态。使用条件有三个硬约束，直接决定了视觉方向：

| 约束 | 后果 |
|---|---|
| 长时间盯着看（分钟级到小时级） | 不能有高饱和大色块、不能有持续动画 |
| 数值每秒变化 | 数字必须等宽（tabular），否则整行在跳 |
| 现场可能断线、脱戴、无 RR | 必须能一眼区分"没数据"和"状态正常" |
| 离线便携包分发，不能联网 | 字体必须用系统自带，图标不能引 CDN |

### 1.2 适用范围

- **适用**：主界面三栏（状态 / 曲线 / 提醒）、详情抽屉、设置抽屉、校准抽屉、Toast 与提示条。
- **不适用**：答辩 PPT、设计稿文档、组员 B 的交互稿（保留各自原貌，不改）。

### 1.3 一句话方向

> **临床仪器面板（Industrial / Utilitarian）**——可信感来自结构：发丝线、对齐、等宽数字、
> 单色符号；**不来自**阴影、渐变、圆角卡片堆叠。

**记忆点**：8 个状态各有一枚自绘的单色线性符号（压力=闪电、焦虑=云、嗜睡=月、
疲劳=电池、分心=对话泡、心流=波、专注=靶、放松=叶、中性=省略号）。
换掉 Logo，这套符号仍然只属于这个产品。

## 三、字体系统

### 3.1 三套栈，各司其职

```css
--font-display: "Bahnschrift", "DIN Alternate", "DIN Condensed", "Barlow Condensed", var(--font-ui);
--font-ui:      "Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", ... ;
--font-mono:    "Cascadia Mono", Consolas, "SFMono-Regular", "JetBrains Mono", ui-monospace;
```

- **Bahnschrift** 是 DIN 1451 血统，Win10/11 自带 → **离线便携包不需要外挂字体**。
  它没有中文字形，汉字会自动落到 `--font-ui`；这是有意的混排（数字 DIN、汉字雅黑），
  不是字体缺失。
- 不用 Inter / Roboto / system-ui 作展示字：那是"正确但无个性"的默认选项。
- 中文用 `Microsoft YaHei UI` 而非 `msyh`：更紧凑，适合界面密度。

### 3.2 字号与排版规则

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-micro` | 10.5px | 角标、英文键名、单位 |
| `--fs-cap` | 11.5px | 说明、标签、得分 |
| `--fs-body` | 12.5px | 正文、按钮、状态名 |
| `--fs-num` | 14px | 指标值、卡片标题 |
| `--fs-sec` | 15px | 小节标题 |
| `--fs-hero` | 18px | 状态名（大） |
| `--fs-display` | 30px | 曲线主数值 |

- 所有数值元素加 `font-variant-numeric: tabular-nums`（指标、得分、置信度、坐标轴）。
- 微标签字距 `+.045em`，**但不加 `text-transform: uppercase`**：
  实测它把 `R_tb` 变成 `R_TB`、`θ` 变成 `Θ`、`I_f` 变成 `I_F`——这些是数学记号，
  大写后就是另一个符号。这是一次真实的误伤，已回退并在 CSS 里写明原因。
- 大数字收紧字距 `-.01em ~ -.02em`；DIN 字面偏窄，正字距会显得松垮。

## 四、间距、圆角、阴影、动效

### 4.1 间距：4px 基准

```
--sp-1: 4   --sp-2: 8   --sp-3: 12  --sp-4: 16
--sp-5: 24  --sp-6: 32  --sp-7: 48
```

已落到实处的容器（不是只定义不用的"装饰令牌"）：
主栅格 `gap/padding` = 16/8、卡片内边距 16、卡头下距 12、指标格 8、
状态格 8×12、状态网格 gap 8、指标网格 gap 8。

### 4.2 圆角与阴影

- 圆角 5 档：`3 / 8 / 10 / 14 / 999`。整体比 v3.11 收一档——仪器面板靠发丝线
  建立层次，大圆角会滑向"卡片 App"。
- 阴影只留 2 档且极轻（`0 1px 2px` / `0 4px 12px + 0 16px 36px`）。
  卡片是**贴**在底纹上的，不是浮起来的。

### 4.3 动效

| 类型 | 时长 | 缓动 |
|---|---|---|
| 微交互（悬停、按压） | 160ms | `ease-out` |
| 常规（面板、抽屉） | 300ms | `cubic-bezier(.16, 1, .3, 1)` |
| 卡片入场 | 300ms，错峰 40 / 100 / 160ms | 同上 |

**交互不位移。** v3.12 之前：状态格悬停上浮 2px、按下缩到 0.985；按钮悬停上浮 1px。
在 8 个相邻小格子里，鼠标所在的格子会"跳起来"，既影响连续点击命中，也和"读数稳定"
的调性相反。现在统一为 **底色变化 + 内阴影** 表达悬停与按压。

`prefers-reduced-motion: reduce` 下关闭全部过渡与入场动画。

## 五、图标系统

### 5.1 为什么自绘

原来用 emoji（⚡🌫️😴🪫💭🌊🎯🍃⏳）。Windows 由 Segoe UI Emoji 渲染，**字重、基线、
彩色填充都不受控**，深色主题里尤其突兀，且无法跟随 `currentColor`。

### 5.2 规格（`js/icons.js`）

```
viewBox 24×24 · stroke 1.7 · stroke-linecap/linejoin round
颜色 = currentColor · 尺寸由 CSS 决定（1em 基准，各场景 13–26px）
纯描边，无填充（play / pause / theme / ellipsis 的实心部分显式 fill）
```

### 5.3 符号表（17 个）

| 类别 | 符号 |
|---|---|
| 品牌 | `pulse`（一段脑电搏动） |
| 操作 | `play` `pause` `step` `reset` `theme`（半明半暗圆盘） |
| 提示 | `alert` `check` `close` `info` `bell` `route` `megaphone` `document` `download` `upload` `sliders` |
| 状态 | `bolt` `cloud` `moon` `battery` `bubble` `wave` `target` `leaf` `ellipsis` |

状态映射写在 `Icons.stateIcon(state)`，业务代码只传状态键，不写 SVG。

### 5.4 使用规则

- 图标**必须有信息含义**，不做纯装饰（反 AI 味清单第 5 条）。
- 与文字混排时 `vertical-align: -.14em`，行内小图标 13px + 右距 4px。
- 状态符号固定在 20×20 的"井"里（底色 = 文字色 7% 混色），保证 8 格视觉同高。
- 门控点颜色跟随状态族：`alert` 族亮红、`warn` 族亮橙、良好族亮绿——
  压力门的"点亮"不能显示成"良好绿"。

## 七、组件规范

### 7.1 卡片

- 结构：`卡头（3px 品牌刻度线 + 标题 + 右置说明）` → 内容 → `卡脚（入口）`
- 边框 1px `--border`，圆角 `--r-lg`(14)，阴影 `--shadow-1`
- 悬停只提亮边框（`--border-strong`），不位移

### 7.2 指标格（6 格 = 3×2）

```
┌─────────────┐
│ ATT / MED   │  ← 11.5px（v3.13 由 10.5 提上来），字距 +.045em，--text-3
│ 76 / 72     │  ← 14px DIN 700，tabular
└─────────────┘
```

- 10.5px 从此只用于「可略读」内容：英文键名、时间戳、角标。判读数字所必需的
  指标名不该是全站最小字号
- 无 RR 通道时：值显示「无 RR」并淡化，指标名后挂 9px「无RR」小签（`hidden` 默认，
  设备带 PPG 时不出现）

### 7.3 状态格（8 格 = 2×4，通道条）

```
┌──────────────────────┐
│ [井] 焦虑          −0.4 │  ← 图标井 20px + 中文名 + 右置得分
│      ● anxiety        │  ← 门控点 + 英文键（左缩进 27px 对齐文字）
└──────────────────────┘
```

- 得分右对齐占首行尾位，**注入徽标出现时得分隐藏**（同一位置，避免叠字）
- 当前态：品牌边框 + 2px 外环；手动注入态：`--brand-soft` 底 + 「注入中」徽标
- **v3.13 证据条**：格子底部 2px，宽度取 `dec.evidence`（0–1）。分数本身无量纲，
  单看"1.71"无从判断强弱；条给出相对刻度，数字保留供核对
- **v3.13 不可判态**：`data-unavailable` → 透明度 .62 + 右上 45° 细斜线 + `cursor: help`。
  无 RR 通道时 `stress` 恒不可判，用它代替"一直等一个不会亮的格子"

### 7.4 按钮层级

| 层级 | 样式 | 用途 |
|---|---|---|
| 主 | 品牌实底 / 运行中为品牌描边 | 开始推流 |
| 次 | ghost（描边） | 单帧、重置、重连 |
| 图标 | icon-btn（描边 + 图标/文字） | 顶栏功能入口 |
| 段控 | seg（分段） | 数据源模式 |

### 7.5 状态覆盖

每个可交互组件覆盖：默认 / 悬停 / 按下 / 聚焦可见 / 选中 / 禁用 / 加载 / 空。
聚焦统一 `:focus-visible` 2px 品牌描边 + 2px 偏移；空态有专用插图与说明；
加载态由 `--dur-base` 过渡承担（无骨架屏，数据是流式的）。

### 7.6 弱判别态（v3.13）

`conf < WEAK_CONF` 时主卡不沿用状态族色：底改 `--surface-2`、边框 `--border-strong`、
状态名降为 `--text-2`、环改虚线圈（不画进度）、加「弱判别 0.6x」徽标。

理由：`stress + conf 0.62` 原本会画成一张红卡，配 SILENT 徽标与"仅记录不干预"，
三个信号互相矛盾。弱判别表达的是"证据不足"，不是"状态严重"。

### 7.7 零样本引导条（v3.13）

冷静度以「决策」为唯一口径，没有决策就没有分母。此时主值显示「—」（中性色，
不是绿色 1.00），下方出一条虚线框引导：一句公式解释 + 买入/卖出/持有三个快捷按钮。
一旦有第一条决策，引导条整条消失。

### 7.8 状态占比环形图（v3.13）

提醒中心底部：SVG 圆环（r=40、stroke 12）+ 右侧图例，最多 6 项。
弧长按帧数占比，颜色取状态族色，图例与弧段同序。
数据源与曲线同源（`S.history`），500ms 节流。
作用是把原来整块的空态留白变成"本次会话谁占多久"。

### 7.9 演示 / 产品形态徽标（v3.13）

标题右侧 24px（触屏 32px）胶囊：演示态橙色、产品态绿色。
产品形态隐藏手动注入 / 粘贴数据 / 单帧 / 格子点击注入，
并卸掉「注入中」徽标与"点击可注入"提示。选择记 localStorage，`?prod=1` 可直达。

### 7.10 分组折叠（v3.13）

设置面板每个分组 = `<details class="fold">`，标题为 `<summary class="grp">`，
箭头用 `::before` 的 ▸ / ▾（旋转 90°），发丝线仍由 `::after` 承担。
默认展开「数据源诊断」「数据流控制」，其余收起。

## 八、响应式（v3.13 重排）

### 8.1 断点表

宽度与高度分开判断：宽度决定"几栏"，高度只决定"要不要一屏塞满"。
混在一起判断会互相误伤（1440×900 一屏刚好，1366×650 必须滚动，两者宽度只差 74px）。

| 断点 | 布局 | 关键决策 |
|---|---|---|
| ≥1720 | 同上 + 顶栏/页脚限宽 | 2560 下品牌与按钮相距 2100px，与下方卡片完全不对齐 |
| >1440 | 三栏 `340 / 1fr / 360`，限宽 1680 | 1920 下左右各留 120，图表不被拉成 2.5:1 |
| 1161–1440 | 三栏 `300 / 1fr / 320` | 只挤两侧固定列，三栏语义不变（1440 时中栏从 728 回到 788） |
| 901–1160 | 两栏 `300 / 1fr`，提醒卡跨整行 | 空态改横向（图标左 + 文案右），高度 132px 以内 |
| ≤900 | 单列 | 指标 2 列、状态网格 2 列、空态回纵向 |
| ≤560 | 单列紧凑 | 顶栏模式段独占一行；隐藏控制条说明；hero 保持横排 |
| ≤400 | 单列极窄 | 隐藏品牌副标题与 tagline；卡片内边距 16→12 |
| **640–900 且高 ≤500** | 两列 | 横屏手机：横向有 844 宽，单列首屏只剩 240px 可用 |
| **高 ≤880** | 放弃"一屏塞满" | 内容流 + 整页滚动。阈值从 780 提到 880 |

### 8.2 为什么高度阈值是 880 而不是 780

左卡内容实测需要 631px（head 34 + hero 130 + 指标 122 + 分组标题 36 + 8 态 248
+ foot 29 + padding 32），加顶栏 68 / 控制条 98 / 页脚 40 后约 840。
旧阈值 780 会让 1180×820 这类屏幕走"填满"分支，8 态网格被压到 174px、
只露 3 行且自带滚动条。820 与 780 只差 40px，但结果完全不同。
880 之下：1440×900 / 1600×900 / 1920×1080 仍是一屏，其余矮屏完整展开。

### 8.3 验收方法（几何量测，不靠目测）

`_rs_audit.mjs`（CDP 驱动无头 Edge）对 15 个断点逐个渲染，每档检查 7 项：
脚本放在开发机工作目录 `C:\Users\DAOCI\WorkBuddy\2026-10-22-21-27-23\_rs_audit.mjs`，
**不进交付包**（依赖本地 9222 调试端口 + 8771 静态服务）。
用法：先起 `python -m http.server 8771`（在 `组员文件/任务一/` 下），
再 `node _rs_audit.mjs <输出目录>`。抽屉专项用同目录的 `_rs_drawer.mjs`。

| 项 | 判据 |
|---|---|
| 横向溢出 | `documentElement.scrollWidth - innerWidth > 1` |
| 元素越界 | 任一非 fixed 元素 `right > innerWidth + 1.5` |
| 区块重叠 | body 顶层层 / `.grid` 子项 / `.card` 子项 三层两两相交，交叠占比 >2% |
| 子元素溢出父容器 | `.card > *` 超出父 padding-box |
| 文字被裁 | `scrollHeight > clientHeight + 2`（overflow hidden） |
| 触控目标 | 桌面 <24px、触屏 <32px |
| 滚动藏内容 | `scrollHeight / clientHeight > 1.25`（需人工判断） |

15 个断点：1920/1600/1440/1366×768/1366×650/1280×800/1180×820/1024/834/768/430/390/375/360/320。

### 8.5 一条踩坑记录

空态在 1160 断点用了 `grid`，900 断点切回 `flex column` —— 但只改了 `display`，
没重置 1160 设的 `align-self: end/start`。在 column 方向上 align-self 作用于横轴，
结果是「标题右对齐、说明左对齐」，文字散到卡片两端。**切换布局模式时必须把
该模式下语义变化的属性一并归零**，只改 display 不够。

## 十一、未做与理由

| 候选 | 为什么没做 |
|---|---|
| 外挂 Web Font（更像"设计感"） | 便携包要求离线，多一套字体就多一份加载失败风险；DIN + 雅黑已够 |
| 主区生成背景图 | 会拉坏对比度，且与线稿语言冲突；只在空态用图 |
| 全量 4px 栅格重排（300+ 处） | 收益在维护性不在观感，本周优先答辩；已把主容器吸收到令牌 |
| 暗色主题的另一种强调色 | 强调色只应有一个；换色会破坏"红=告警"的语义纪律 |
