## 1. 接蓝牙 → 认 COM（最容易白花一小时的一步）

1. 头环开机；手机端 **BrainLink App 先断开**（串口被独占时打不开，是最高频失败原因）
2. 系统蓝牙配对：列表里可能出现两个同名设备 → **选名字前带耳机图标的那个**
3. `设备管理器 → 端口(COM 和 LPT)` 记下 COM 号

配对后会生成**两个**虚拟 COM 口：**必须选「传出 / 输出」那个。**

| 候选 | 能不能用 |
|---|---|
| 「传出 / 输出」口 | ✅ 唯一正确 |
| 「传入」口 | ❌ **能打开、不报错、但永远 0 字节**（极具欺骗性） |
| **COM1**（主板自带） | ❌ **永远不要选**——同样能打开、同样静默 |

分辨"传出"：蓝牙设置 → 更多蓝牙选项 → COM 端口 → 看哪个标着**传出**。

## 2. 预检（录制前 30 秒，把三种坑一次拦掉）

```bash
python preflight.py                    # 列出全部 COM 并逐个空跑 30s
python preflight.py --port COM5        # 已认准口，只探这一个
```

看结论行，**不是 PASS 就照它给的「→」提示处理**：

| 结论 | 属于哪个坑 | 怎么办 |
|---|---|---|
| `串口打不开` | 被 App 占用 / 口号不存在 | 断开手机 App；回设备管理器确认编号 |
| `N 秒内零字节` | **口选错** 或 **头环休眠** | 换另一个 COM（传出）；唤醒/重启头环 |
| `有字节但 0 有效帧` | 波特率或协议不匹配 | 试 `--baud 57600` |
| `接触无效帧 >10%` | 能解帧但**没戴好** | 调额贴/耳夹、拨开头发，重跑 |
| `PASS` | — | 进 D1 |

> 等价判据（不用本脚本时）：`serial_bridge` 有 **15s 静默看门狗**，
> 出现 `[警告] 已 15s 未收到任何字节` = 口选错；出现 `已收到数据（累计 N 字节）` = 真的通了。

## 3. D1 首次联通（目标只是"看见数据"，先别管状态对不对）

```bash
cd 项目文件
python serial_bridge.py --port COM5 --baud 115200 --record data/rec_first.csv
```

**先看启动第一行**打印的解析器来源：

| 第一行显示 | 意味着 |
|---|---|
| `纯 Python tgam_parser` | ✅ 预期（**官方 pyd 已放弃**：不在 PyPI + 需 Py3.11）→ 本批数据**必然没有 RR/心率/gyro** |
| `官方 BrainLinkParser.pyd` | 异常，核实 Python 版本 |

戴好头环采 **2 分钟**，Ctrl+C 停止，然后**只跑一条命令核验**（不看表、不猜）：

```bash
python verify_hw.py --all data/rec_first.csv
```

判读：

- `signal` = TGAM poorSignalLevel → **0 最好、200 电极未接触皮肤**（方向别搞反）
- **V1（RR/心率）FAIL 是预期不是故障**——纯 Python 解析路线拿不到 RR，
  代价是 **8 态里 stress 一态不可判**，其余照常，HRV 判据降级为佐证
- 这条链已**无真机预演通过**（mock 录制 → `--all` → V3 PASS + V1 PASS = 2/2），
  所以真机采完若 FAIL，锅在**硬件/佩戴/选口**，不在代码

## 4. D2 三段校准（每人 5 分钟）

```bash
python live_bridge.py --source serial --serial-port COM5 --baud 115200
# 浏览器 http://127.0.0.1:8770 → 数据源切「真机」→ 右上「校准」→ 勾「完整协议时长」→ 开始
```

| 段 | 时长 | 受试者做什么 | 产出 |
|---|---|---|---|
| A 闭眼静息 | **30s** | 闭眼、不想事、不说话 | δ 基线 + `theta_rest`（仅参考） |
| B 睁眼静坐 | **120s** | 睁眼看十字、不做任务 | 全部 z 基线 + **`theta_ref`** |
| C 放松 | **120s** | **闭眼**、深呼吸、肩放松 | 放松锚点 `c_anchor_z` |

**三个数决定"能不能开跑"：**

1. `ok = true`（伪迹率 <30%）— 否则重戴，**别带着坏基线开跑**
2. `theta_ref_src = "B"` — 显示 `A-fallback`/`default` = B 段没采够，重采
3. `c_anchor_z` ≥ 门控值 → relaxed 可判；否则该受试者 relaxed 标"降级"

导出的 `baseline.json` **一人一份，不跨人复用**（θ/δ 个体差异远大于组间差异）。

## 4b. 用命令行采原始 dump（写报告/离线分析用这条）

`live_bridge` 是"看界面 + 存基线"；要留**原始全量数据**（事后判 RR 有没有推、
重跑分析、做双引擎对账），用 `collect_real.py`。

### 补测用这条（5 段，约 6 分钟，一次补齐校准 + V4）

```bash
python collect_real.py --port COM5 --subject sub01 --preset d2v4 --stop-after-preset
```
或直接双击 `启动-真机补测采集.cmd`（自动用包内运行时，不用敲命令）。

| 序 | 段 | 受试者做什么 | 时长 |
|---|---|---|---|
| 1 | D2_A | 闭眼静息（不做事、不说话） | 30s |
| 2 | D2_B | 睁眼看十字、不做任务 | 120s |
| 3 | **D2_C** | **闭眼**放松深呼吸 ← 闭眼是硬要求 | 120s |
| 4 | V4_SILENT | 静默不动、不说话不吞咽 | 40s |
| 5 | V4_TALK | 正常音量说话或朗读（不必大喊） | 40s |

> **C 段为什么必须闭眼**：α 主要靠闭眼升高（实测闭眼 α ≈ 睁眼的 2.8–3.4 倍）。
> 2026-11-09 那批数据 C 段只写"深呼吸"没写闭眼，α 只到睁眼基线的 0.96–1.55 倍，
> `c_anchor_z` 全部 <1.5（0.51/1.23/-0.01）→ relaxed 态判不出来。
> 按 A 段实测水平推算，闭眼后 z≈+1.76/+2.96/+1.55，三份都能过。

> **V4 两段为什么必须成对**：判据是"说话段伪迹拦截率 ≥90% 且静默段误报 ≤10%"，
> 只有说话段没法算误报。静默段前 24s 建基线、后 16s 测误报。

**采集中只认两个输出（缺一不可）：**

| 必须看到 | 含义 | 没看到怎么办 |
|---|---|---|
| `✓ 首帧已到：signal=0` | 链路真的在推数据 | 20s 内没出现会自动中止——查「传出」口 / App 占用 / 休眠 |
| `✓ 「D2_A」本段收到 N 帧` | 这一段真的落了盘 | 出现 `✗ 本段零帧`：**立即停下**，别接着往下采 |

> **2026-11-09 首采的教训**：旧版脚本在 `input()` 等待时根本不读串口，
> 三段校准 6 分 30 秒一帧未采（数据全丢），回家跑分析才发现。现已改为后台线程读串口，
> 且每段结束自报帧数。**现场看到两个 ✓ 再往下走**：A 段约 30 帧、B/C 各约 120 帧、V4 各约 40 帧。
