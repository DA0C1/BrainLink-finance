### 增量 13（2026-10-23·阶段 B 准备 + 三处真实缺陷修复 + 一处判断纠正）

**前提**：任务 4 验收完成（有条件通过），四任务全部闭环。本轮不重打分发包、不改组员交付脚本，只做两件事：为阶段 B 铺可执行路径，以及**校验"已验收通过"的代码里还有没有隐性失效**。

#### 一、核心发现：RR 三值链路三重失效，RMSSD 在回放路径上恒为 nan

验收记录写的是"录制→回放闭环 PASS（两端同判 focus）"。复核后发现这个结论**不足以证明链路正确**——focus 不依赖 RMSSD 精度，所以缺陷被完全掩盖。

| 环节 | 原实现 | 后果 |
|---|---|---|
| 录制 | `on_rr` 循环里 `last_rr[0] = float(r)`，只留**最后一个**间期 | 一次 `onRR` 带 3 个连续间期，落盘丢 2/3，且**不落批次号** |
| 回放 | `adapter.onRR(float(rr), 0, 0)` | `rr2/rr3` 被过滤 → 每个 RR 各占一个批次、每批仅 1 个元素 |
| 引擎 `_rmssd` | `if r0[1] != r1[1]: continue`（同批才差分，v2.6 刻意设计） | 相邻对全部跨批 → `diffs` 为空 → **RMSSD 恒 nan** |
| mock 自检 | `adapter.onRR(x, 0, 0)` 同上 | 断言只查 `len(rr_buf) > 0` → **弱断言照样通过** |

**实测证据**（同一份 160 帧 CSV）：
- 修复前写法：RR 缓冲 13 个、`RMSSD=nan`
- 修复后（三值同批落盘 + 整批回放）：RR 缓冲 39 个、`RMSSD=11.4ms`，与手算一致
- 旧格式 CSV 回放：RR 13 个、`RMSSD=17.0ms`，并主动提示"降级口径"

影响面：RMSSD 是 stress/anxiety 的关键特征。回放调参在 HRV 维度上**完全失效**，且系统性"少判压力"——而调参正是阶段 B 的核心动作。

#### 二、判断纠正：组员版在 RR 这一点上**比权威版正确**（增量 12 写反了）

增量 12 原文："组员版 data_recorder 包装录制思路已等价被权威 Recorder 覆盖。组员版独立价值低优先记录。"

**这句错了。** 组员版 `data_recorder.py`：录制用 `_rr_pending` 保留 `rr1/rr2/rr3` 三值，回放调 `adapter.onRR(rr1, rr2, rr3)` 整批喂回——**它是对的，权威版是错的**。

正确表述：平行实现不是重复劳动，这一处是组员版发现了组长版的漏洞。已按组员版口径修正权威版：

- `CSV_FIELDS` 增 `rr1/rr2/rr3`（保留 `rr_ms` 兼容旧 CSV）

## 补充 14：阶段 B 前置攻关——signal 语义纠错 + 纯 Python 解析器落地

*2026-10-23 · 组长 E*

本轮起因是校对执行清单时顺手核了两个外部事实（官方仓库 README、NeuroSky 协议文档），
结果挖出一个**阻塞级缺陷**和一个**可提前消除的风险**。

#### 一、🔴 阻塞级：`signal` 语义方向整体反了

**事实**：`signal` 透传的是 TGAM **poorSignalLevel**——**0 = 信号最好，200 = 电极未接触皮肤，数值越大越差**。
依据 NeuroSky《MindSet Communications Protocol》原文 *"The higher the number, the more noise is detected.
A value of 200 has a special meaning, specifically that the ThinkGear contacts are not touching the user's skin"*；
ThinkGear Socket Protocol 亦写明 *"0 indicating a good signal and 200 indicating an off-head state"*。

**原实现**：`SIGNAL_GOOD = 200`、判 `signal >= 200` 为「良好」、`--signal-min` 做下限过滤。
**后果**：真机上**好帧全被丢弃、只放行「脱戴」帧**——采集会「有数据但全是垃圾」，且极难现场定位。

**为什么离线测试全绿**：合成数据用 `signal=230`——**已超出 0–200 协议上限，本身就非法**。
测试数据按错误假设生成，判据自然永远通过。这是本项目第二次遇到同一类问题
（第一次是 RMSSD 恒 nan 而「RR 已入缓冲」弱断言照样通过）：**测试自证比没有测试更危险**。

**已修**（全链路一次改完，非局部补丁）：

| 文件 | 改动 |
|---|---|
| `verify_hw.py` | `SIGNAL_OFFHEAD=200` / `SIGNAL_GOOD_MAX=100`；V3 改判**已佩戴占比**（硬门槛，不循环论证）+ 输出 P50/P90 供标定；新增**反例·全程 200 必须 FAIL**；合成数据 230/220 → 30/55 |
| `sdk_adapter.py` | `signal_min`→`signal_max`；`signal>=200` 硬门直接丢（不受参数影响）；`SDKFrame.signal` 默认 200→0 |
| `serial_bridge.py` / `live_bridge.py` | CLI 改名 `--signal-max`（旧参数直接报未知参数，不静默反向） |
| `verify_v30.py` | 合成数据 `signal=200`→`30` |
| 文档 | 清单新增 §1.4；速查补数值口径；组员版 README 加「过时口径」警示 |

**顺带修掉一个 Python 真值陷阱**：`serial_bridge.py` 回放原写
`signal=int(float(row.get("signal") or 200))`——`or` 会把 **`signal=0`（最好）当成假值替换成 200（最差）**，
恰好是最差情况被当成最好。已改 `or 0` 并加注释。

#### 二、纯 Python 自解析：从「待评估」到「已落地」

官方 `BrainLinkParser.pyd` 为**闭源二进制**、README 标注 **Python 3.11**，本机 3.13.14 → 大概率不可用。
评估结论是**按通道分裂**而非一刀切：

- ✅ **EEG 主干全部自解**（`tgam_parser.py`，~300 行）：signal / eSense / 8 频段 / raw
- ❌ **RR、心率、血氧、gyro、扩展包拿不到**——BrainLink **私有协议，无公开规范**；
  且 Python SDK **只有 `parse()`，没有 Android 侧 `setDataType()` 那类下发能力**，
  所以"装了官方 pyd 就一定有 HRV"也不成立

**代价已实测量化**（同形态切换「灌不灌 RR」对照）：

| focus / distracted / relaxed / anxiety | 全部正常判出 | 同样正常 |
| **stress** | **neutral 0.60（判不出）** | **stress 0.95**（RMSSD 3.2ms） |
