# 真机校准实操清单（G4）

> 对应《阶段二项目规划交接文档》§六 校准协议 + §5.3 参数决策映射表。
> 适用：BrainLink TGAM 类单通道头环，串口 115200。
> 目的：让"换一个受试者就能跑"成为可复制的流程，而不是靠操作者手感。

**一句话原则**：校准不是"戴好就点开始"，而是**三段采集 + 一份可判定的报告**。报告不过，就不进入判别——宁可重戴，不要带病开跑。

---

## 一、准备（每次实验前 5 分钟）

| 步骤 | 动作 | 判据 |
|---|---|---|
| 1 | 头环电量 ≥ 50%，开机自检灯正常 | 灯常亮/缓慢闪 |
| 2 | 额头触片用酒精棉擦净，去掉油脂 | 触片无明显污渍 |
| 3 | 受试者静坐，**不要刚运动完、不要刚喝完咖啡**（咖啡因见 §五 V5） | 静息心率接近个人常态 |
| 4 | 耳夹夹耳垂，额头触片贴正中偏上 | 不夹头发、不压眉 |
| 5 | 打开串口桥，看 signal 档位 | 稳定 ≥200（V3 标定后按实测收紧） |

**V3 先做**：`python verify_hw.py --v3 rec.csv`，良好档占比 >80% 才继续。档位飘 = 后面全是白采。

---

## 二、三段校准（协议节奏 30s / 2min / 2min）

软件入口：任务一界面 → 右上「校准」抽屉 → 勾选「完整时长」→「开始三段校准」。

| 段 | 时长 | 受试者指令 | 采什么 | 为什么不能省 |
|---|---|---|---|---|
| **A 闭眼静息** | 30s | 闭眼，不想事情，不说话 | δ 基线 + θ 静息参考 | δ 是嗜睡（drowsy）的佐证判据；无 δ 基线则嗜睡只能单判据降级 |
| **B 睁眼静坐** | 120s | 睁眼看屏幕中央十字，不做任务 | R_tb / R_ba / TAR / α / A_rel / HR / RMSSD / still 全部 z 基线 + **θ_ref** | 这是**主任务**的参照系（B 段本身**不做事**，是中性基线，不是专注任务）。**θ_ref 必须取 B 段**：A 段闭眼 θ 系统性偏高，用 A 会让疲劳积分永不触发（v2.9.2 已修，勿回退）。注意别把"参照系"读成"B 段要专心"——`Z_CONC=−1σ`/`Z_DIST=+1σ` 要求基线落在专注与分心之间的中点，B 段若采专注任务，focus 判据永远够不到 |
| **C 放松** | 120s | **闭眼**、深呼吸、肩放松、可听轻音乐 | 放松锚点 z（c_anchor_z） | 用来验证"这个人的放松态在当前 α 基线下判得出来"；不采则放松判据是盲的 |

**B 段要点**：必须是"睁眼 + 静坐 + 不看强光"。闭眼、说话、动身体都会污染 θ_ref。

**快速模式（15/40/40s）** 仅用于联调走通链路，**正式采集不得用**——B 段是全部 z 基线的来源，40s 只有约 33 帧，σ 估不稳。完整模式 30/120/120s 与设计文档 §六 一致。

## 三、看报告：三个数字决定能不能开跑

校准完成后，界面「校准报告」会给出：

| 指标 | 通过线 | 不通过说明什么 | 处置 |
|---|---|---|---|
| 段样本 A/B/C | 各 ≥10 帧 | 采集被打断 / 帧率异常 | 重做该段 |
| 伪迹帧占比 | ≤30% | 接触不良、眨眼过多、说话 | **重戴后重做**，不要硬跑 |
| C 段放松锚点 z | ≥1.5 | 该受试者放松态在当前 α 基线下不可判 | 加强放松引导重做；仍不行则在实验记录里标注「放松态判据不可用」 |
| θ_ref 来源 | 显示 `B` | 显示 `A-fallback` / `default` 说明 B 段数据不足或未校准 | B 段重做；`default` = 根本没校准，**禁止开始正式实验** |

报告通过后点「导出基线」，得到 `baseline.json`——**一个受试者一份，不要复用**。

## 四、串口桥与回放（把数据推进界面）

```bash
# 真机实时（实验当天）
python live_bridge.py --source serial --serial-port COM3 --baud 115200 \
                      --baseline baseline.json

# 无真机排练 / 答辩演示（可循环）
python live_bridge.py --source replay --csv data/rec_20261023_1400.csv --speed 1 --loop

# 纯合成数据（验证链路，不代表判别准确率）
python live_bridge.py --source mock
```

打开界面 → 顶部模式选「真机/回放」→ 抽屉「连接」填 `http://127.0.0.1:8765` → 连接。
状态栏显示帧计数即为通。

**录制**（为回放/复盘准备）：

```bash
python serial_bridge.py --record data/rec_$(date +%Y%m%d_%H%M).csv --baseline baseline.json
```

录制逐行 flush，Ctrl+C 中断不丢已写数据。

## 五、校准后的参数决策（V 系列验证）

按《规划》§六 顺序：**V3 → V1 → V2 → V4 → V5**，一条命令一项：

```bash
python verify_hw.py --all rec.csv                      # V3 + V1
python verify_hw.py --v2-closed closed.csv --v2-open open.csv
python verify_hw.py --v4-silent silent.csv --v4-speak speak.csv
```

| 项 | 通过线 | 不过怎么办（5.3 表预案） |
|---|---|---|
| V1 RR 质量 | 丢失 <10%、超生理 <5% | 放宽 `Z_STRESS` −1.5→−1.2 或加长 HRV 窗；极差则 HRV 判据降级为佐证，答辩标注 |
| V2 δ 可测性 | 闭眼 vs 睁眼 δ 中位数相对差 ≥20% | drowsy 改单判据 `TAR>+1.5`（去掉 δ 合取），文档标注降级原因 |
| V4 说话肌电 | 朗读帧拦截 ≥90% | 若 8× 门不够 → 把 `state_engine.py` 与 `任务一/js/engine.js` 的 `ARTIFACT_EMG_GATE` **同时**改 `True`（β+γ 同升且 θ 不动专用门）；两处必须一起改，`verify_parity.py` 会卡 |
| V5 咖啡因（可选） | 描述性，不作门禁 | β/HR 同升 → 应用层提示"咖啡时段判据降权"；否则标注个体差异大 |

**V4 特别说明**：8× 伪迹门是"突变检测"，对**持续**肌电（说话、咬牙）会饱和——首帧爆发触发一次，之后平滑基线被抬上去，后续帧不再超 8×。所以朗读段必须单独测，不能靠主任务"看有没有提醒"。

## 七、常见问题与处置

| 现象 | 最可能原因 | 处置 |
|---|---|---|
| signal 档位一直 <200 | 触片有油 / 头发夹在中间 / 电量低 | 擦触片、重新贴、换电池 |
| 伪迹率 >30% | 眨眼频繁、说话、头在动 | 让受试者静 30s 重采；仍高则重戴 |
| θ_ref 来源显示 default | 没点校准就开始跑 | 回 §二 做三段校准 |
| C 段 z < 1.5 | 受试者没真放松（紧张/好奇） | 加长引导、闭眼+深呼吸；记录标注 |
| 判不出疲劳 | θ_ref 取了 A 段（旧版本）/ 受试者本就不疲劳 | 确认 `theta_ref_src="B"`；确认任务确实诱发了疲劳 |
| 界面收不到帧 | 桥没起 / 端口被占 / 模式没切「真机」 | 看 `/health`；换端口；切模式 |

## 八、纪律（写在这里是为了答辩时能照读）

1. **不臆造参数**：本清单所有阈值都是"经验初值"，真机实测后改代码里**一处**（常量区），并在记录表留痕。
2. **不跳过失败**：报告 `ok=False` 就重戴重做，不做"先跑跑看"。
3. **口径如实**：降级判据（HRV/δ/V4 门）一旦启用，答辩与论文里必须写明降级原因与影响。
4. **一人一份 baseline.json**，与受试者编号一同归档，不跨人复用。
