## ① 状态判断与反馈：9 个状态都接上了，但边界情况没有"说出口"

### 适配矩阵（引擎实测枚举）

| 状态 | 等级 | 色族 | 冷却 | 话术 | 网格位 |
|---|---|---|---|---|---|
| stress 压力 | calm | alert | 60s | 有 | 有 |
| anxiety 焦虑 | calm | alert | 60s | 有 | 有 |
| drowsy 嗜睡 | calm | alert | 60s | 有 | 有 |
| fatigue 疲劳 | mild | warn | 60s | 有 | 有 |
| distracted 分心 | mild | warn | 60s | 有 | 有 |
| flow 心流 | silent | good | 0 | 有 | 有 |
| focus 专注 | silent | good | 0 | 有 | 有 |
| relaxed 放松 | silent | good | 0 | 有 | 有 |
| neutral 中性 | silent | idle | 0 | 有 | **无**（不在 PRIORITY） |

**结论：映射层面没有遗漏项**。但有三处边界没有交代：

**①-A 不可判状态无任何提示（P0）**
`stress` 的门控是 `gz('RMSSD_60') < Z_STRESS`（`engine.js:651`）。本机无 RR 通道，
`RMSSD_60` 恒为 NaN，比较恒 false → **压力永远不亮**，但界面上它和"这一帧没过门控"
长得完全一样（得分显示 `—`）。同一问题还出现在两个指标上：`RMSSD` 永远显示
"窗口未满"（`app.js:687`），用户会以为"再等等就有了"，其实永远不会有。

**①-B 弱判别时颜色和等级互相打架（P1）**
主卡色族取的是**状态**（`app.js:657` `el.stateHero.dataset.family = m.family`），
等级取的是**反馈**。当 `conf < 0.7` 时反馈降为 `silent`（"弱判别，仅记录状态"），
于是出现「红色告警底 + SILENT 徽标 + 文字说只记录不干预」的三重矛盾。

**①-C 四级实为三级（P1）**
页脚写"8 状态 + **4 级提醒**"（`index.html:167`），但引擎只会产生
`silent / mild / calm`（`engine.js:740-770`）；`strong` 仅存在于 CSS 与
`TOAST_LIFE`，全库没有任何路径产生它。提醒中心的 `silent` 筛选也只能筛到
系统消息（状态类提醒在 `app.js:628` 就被 `level !== 'silent'` 挡掉了）。

## ② 状态统计：三条曲线三种时间窗，且零样本时显示"满分"

这一节是本次审查**最需要改**的部分。

### ②-A 零决策 = 1.00 满分（P0，会直接误导判断）

```js
get calmness() {                       // engine.js:390
  return this.log.total ? 1 - (this.log.impulsive / this.log.total) : 1;
}
```

`log.total === 0` 时返回 **1**（"100% 冷静"）。运行时实测（推流 9 秒、不做任何决策）：

```
calm = "1.00"      颜色 rgb(15,157,118) = 绿色 good
roll = "近 10 次决策 —"
imp  = "0"         isImp = "—"
```

即：**一次决策都没有，界面却用绿色大字告诉你"理智度满分"**，曲线也画成一条贴顶的绿线。
这是最容易被评委一眼抓住的问题，因为它把"无数据"表达成了"最好结果"。

### ②-B 统计的样本来源藏在抽屉里（P0）

"决策"只来自详情抽屉里的「买入 / 卖出」两个模拟按钮（`app.js:1477-1484`）。
主界面没有任何提示，于是：

- 不点抽屉 → 永远是 `1.00`（见上）；
- 点一次卖出且当时被判为冲动 → `1 - 1/1 = 0.00`，直接变红零分。

一个样本就能把指标打到两个极端，且**没有分母展示**。

### ②-C 三条统计、三种时间窗、三套量词

| 展示项 | 算法 | 窗口 | 量词 |
|---|---|---|---|
| `calmness 累计` | 1 − 冲动数/总决策数 | **整个会话** | 次 |
| `↑回升 0.3pt / 近 24 帧` | 后半窗均值 − 前半窗均值 | **24 帧** | 帧 |
| `近 10 次决策 0.92` | 最近 10 次决策滚动 | **10 次决策** | 次 |
| 曲线范围 `近 120 / 全部` | 采样点数量 | **120 点** | 点（`最近 N 点`） |

四个窗口、三个量词、没有一个说明彼此关系。用户看到"近 24 帧"和"近 10 次决策"并排，
无从判断哪个更可信。另外 `累计` 是"全时段冲动占比的补数"，不是"累计量"，
但也没有任何地方给出分母（总决策数只在抽屉里）。

### ②-D 8 态得分没有量纲（P2）

得分是加权和（`engine.js:660-680`），取值范围无上界也无归一化：实测出现过 `1.71`、`1.77`。
未过门控时写 `-Infinity`，界面渲染成 `—`——与"没有数据"共用同一个符号。
图注只写"数字=加权得分"，读者无法判断 `1.71` 是"很高"还是"刚过线"。

## ③ 场景契合与主流审美：风格立住了，但产品形态还带着演示外壳

**做得对的（不建议动）**

- 仪器面板方向与"盯盘长时间盯看"匹配：发丝线、等宽数字、单色符号、低饱和底纹；
- 语义色纪律清晰（红=告警、橙=注意、绿=良好、灰=中性），双主题对比度 18/18 达标；
- 8 态专属符号是真正的记忆点，比通用图标库有辨识度；
- 响应式四档 + 矮屏策略，1440/1366×650/1024/768/390 实测无溢出。

**不够好的（按影响排序）**

| # | 问题 | 实测证据 | 影响 |
|---|---|---|---|
| ③-1 | **演示控件占据主位** | 顶栏第一排是「自动轮播 / 手动注入 / 粘贴数据 / 真机回放」4 个数据源模式 + 「单帧 / 重置」，全是测试装置 | 真实用户（交易员）看到的是"调试面板"，不是"盯盘工具"；答辩时也会被问"这些按钮给谁用" |
| ③-2 | **字号整体偏小** | 92 个文本节点中 **54 个 ≤ 11.5px**（10.5px 有 25 个） | 分钟级以上的持续盯看会疲劳；投影/答辩现场更难读 |
| ③-3 | **图表数据墨水比低** | 画布 620×425，只有一条线；Y 轴 0.80–1.00 三格空白 | 三分之一的屏幕面积只表达一个数，且该数在左上角已经用 30px 写了一遍 |
| ③-4 | **空态吃掉整卡** | 空态 324×535，卡片 360×669（**80%**） | 右栏长期是一大块空白，三栏视觉重量失衡 |
| ③-5 | **中英混排术语未本地化** | `att/med`、`R_tb (θ/β)`、`I_f`、`CALMNESS`、`conf` | 非本组观众读不懂；答辩需要口头解释，占时间 |

## ④ 元素意图：一级清楚，次级含糊

**清楚**：开始/暂停推流、8 态格子（图标+中文名+得分+门控点）、指标格、状态等级徽标。

**含糊的 5 个**：

| 元素 | 问题 | 建议 |
|---|---|---|
| `单帧` | 运行中按它只是"多推一帧"，语义不明 | 仅暂停时可用，文案改「前进一步」并加 title |
| `近 120 / 全部` | 120 是"点"还是"秒"？ | 改「近 120 帧（≈2 分钟）」 |
| `图例 / A·B 对照 →` | 一个按钮两个主题，且图例已经在卡片底部有了一行 | 拆开或改「A/B 段对照 →」，图例只留一行 |
| `查看详细判别 →` + 顶栏`详情` | 同一抽屉两个入口 | 保留其一（顶栏），卡片脚注改文字说明 |
| 8 态格子"点击可注入" | 点击会改变数据源相位（演示行为），与"查看"预期不符 | 演示模式下才可点，且加虚线边框提示 |

**可读性具体证据**：主卡"状态名 18px / 建议 12.5px"（实测 `stateFs=18px`、`actionFs=12.5px`）。
对盯盘场景来说这是**优先级倒置**——用户最需要的是"我现在该做什么"，
界面最突出的是"你现在是什么状态"。

## ⑥ 设计与功能冲突：5 处

| # | 冲突 | 证据 | 后果 |
|---|---|---|---|
| **6-1** | **零样本显示满分** | `engine.js:390` + 实测 `calm=1.00` 绿色 | 把"无数据"读成"最佳状态"，是本次最严重的语义错误 |

## ⑦ 响应式：15 档实测（v3.13）

用 CDP 驱动无头 Edge，对 1920/1600/1440/1366×768/1366×650/1280×800/1180×820/
1024/834/768/430/390/375/360/320 逐个渲染，每档量测 6 项（横向溢出、元素越界、
区块重叠、子元素溢出、文字被裁、触控目标），并抓全页截图人工复核。

**结论：15 档全部无溢出、无重叠、无裁切、无过小触控目标。**

改前改后的关键差异：

| 断点 | 改前 | 改后 |
|---|---|---|
| 1180×820 | 8 态只露 3 行 + 内部滚动条 | 8 态完整，页面高 901 |
| 1024×768 | 提醒卡空态占 380px 高、两侧各空 300px | 横向空态 120px，整体居中 |
| 1600×900 | 8 个状态格英文 key 各被切 3px | 无裁切 |
| 390×844 | 页面高 2636，指标/状态各占 6/8 行 | 页面高 1970（省 25%） |
| 320×568 | 品牌副标题折成 3 行、卡片标题拆字 | 顶栏 2 行、标题单行 |
| 2560×1440 | 顶栏横跨 2560，与 1680 内容区错位 | 对齐到同一列 |

仍存在的取舍（非缺陷）：

- **1366×768 需滚 222px**：三卡内容合计 944，物理装不下 768。这是内容量决定，不是布局问题。
- **≤900 单列时页面长 1970–2250**：手机上一次看一张卡是可接受的信息密度。
- **设置抽屉在 320 下滚动比 4.5×**：设置项 20 余条，可考虑分组折叠（P2）。
