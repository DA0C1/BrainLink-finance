## 零、一句话定位

做一个**能被检验、也能被卡住**的提醒层：用消费级单通道脑电头环（BrainLink，额区干电极，1 Hz），
判 8 种认知/情绪状态，在合适的时候给出分级提醒，并把"为什么这么判"全部摊开。

**明确不做什么**：不宣称判别准确率（无金标准标签）、不做医学诊断、不外推投资建议。

### 1.1 分工方式（按任务切片，不按人切片）

| 角色 | 负责什么 | 说明 |
|---|---|---|
| **组长（主干）** | 阶段一文献综述与映射表 · 状态引擎（8 态判据 + 校准 + 双引擎对拍）· 数据链路（串口/回放/SSE）· 四任务验收 · 真机联调现场 · 答辩材料 | 贯穿全周期；所有"跨任务的口径"由组长收口 |
| **四项任务各一名组员** | 见下表 | **自行认领、一人一项、先到先得**；建议按各自文献背景选（任务1 偏 β 波、任务2 偏 θ·δ、任务3 偏 γ·HRV、任务4 偏 α 波） |
| **真机采集** | 由 1 名组员作为受试者执行五段协议 | 组长负责脚本、现场口令与数据分析 |

| 任务 | 一句话 | 交付物 | 依赖关系 |
|---|---|---|---|
| 任务 1 | 引擎能判状态，缺"用户怎么看" | 交互稿 + 可运行前端 | 无 |
| 任务 2 | 项目要证明"提高决策理智度"，需可量化 | 验证方案文档 | 其"任务需求清单"是任务 3 的**前置**（10-21 先交） |
| 任务 3 | 理智度实验要跑的任务环境 | 模拟盯盘平台（脚本 + 前后端） | **等任务 2 需求清单** |
| 任务 4 | 真机寄到前备齐工具 | 串口桥 + 录制器 + 5 项验证 | 无 |

**为什么这样分**：四项任务的耦合点只有两个 —— ①任务 2 的指标口径必须与引擎一致；②任务 3 的状态字段必须与引擎一致。
把这两个耦合点交给组长收口，其余四项可以真并行，互不阻塞。事实上任务 2 提前两天交需求清单，任务 3 才没有空转。

### 2.1 阶段一 · 文献调研（已完成）

| 项 | 结果 |
|---|---|
| 纳入文献 | **26 条，全部 VERIFIED**（原 3 条 MINOR 已补全 DOI 与卷期页码后升级） |
| 证据分级 | **Ⅰ** 系统综述/Meta/N≥50；**Ⅱ** 20≤N<50 或高质量预印本；**Ⅲ** N<20/侵入式/科普 |
| 交付物 | 综述报告（提交版 + 完整版）、附件1 证据地图与矛盾清单、附件2 阅读卡总表 26 条、附件3 参考稿 |
| 核心产出 | **《脑波-心率与状态映射关系表》**：以 BrainLink 的 8 个数据维度为行，逐行给"对应状态 → 文献证据 → 一致性 → 矛盾点 → 设备适用边界" |
| 关键判断 | **13 个矛盾点显式列出**（α 符号翻转、θ 悖论、疲劳 θ↑ vs 嗜睡 θ↓、干湿电极等效性、FAA 不可实现……），并给每条写处理口径 |

**这一步的价值不在"读了多少篇"，而在"把不能判的地方提前标出来"**。例如 FAA（额区 α 左右不对称）文献支持很强，
但单通道头环物理上算不出发左右差 —— 这种事前写进映射表，答辩时就不会被问倒。

### 2.2 任务 1 · 输出 / 提醒层 UI（已完成并持续迭代到 v3.16）

| 模块 | 实现方式 |
|---|---|
| **8 态面板** | 每个状态一格，显示中文名 + 英文键 + 加权得分 + 2px 证据条；点亮 = 当前判定；弱判别时改虚线环并标「弱判别」 |
| **置信度** | 环形进度（SVG）+ 中心数值；`conf = 0.6 + 0.35·sep·strength`，< 0.7 判为弱判别 |
| **4 级提醒** | silent / mild / calm / strong；`strong` 由同状态 600s 内第 3 次 `calm` 升级产生（输出层实现，不动引擎判据） |
| **提醒中心** | 事件流 + 按级别筛选 + 未读角标 + 弹窗 + 语音（Web Speech）+ 震动；噪声条目（冷却中/弱判别/数据不足）不入列表 |
| **冷静度曲线** | 冷静度 vs 决策时刻的折线；零样本时显示「—」并给三个快捷决策入口；悬停显示十字线与该点状态 |
| **6 项指标** | att/med、R_tb(θ/β)、RMSSD₆₀、HR、I_f 积分、电极接触；每项带公式与阈值 tooltip；无 RR 时明确标「无 RR」 |
| **状态占比环** | 本次会话 8 态占比，与曲线同源（`S.history`），500ms 节流 |
| **CSV 导出** | 概览（帧/伪迹/决策/冷静度/校准/RR 通道）+ 8 态占比 + 提醒明细，带 UTF-8 BOM，双击可开 |
| **演示/产品双形态** | 标题旁徽标切换；产品形态隐藏手动注入、粘贴、单帧按钮与「注入中」标记 |
| **响应式** | **15 档实测**（1920×1080 → 320×568），零溢出/零重叠/零裁切；宽度决定栏数，高度只决定"要不要一屏塞满" |
| **无障碍** | 57 个按钮全部有可访问名称；`focus-visible` / `prefers-reduced-motion` / `aria-live` 齐备 |

技术形态：**零第三方依赖**、纯 `<script>` 标签（`file://` 可直开）、断网可用、暗色主题。

### 2.3 任务 2 · 理智度验证方案（已完成）

定义三项可复算指标，口径全部与引擎对齐：

| 指标 | 公式 | 数据来源 |
|---|---|---|
| **冲动率 / 冷静度** | `冷静度 = 1 − 冲动决策数 / 总决策数` | 引擎 `log.impulsive` / `log.total` |
| **专注态占比** | `(focus + flow 累计时长) / 有效盯盘时长` | 任务脚本逐帧打标（引擎不落逐帧日志） |
| **提醒响应率** | 提醒后 ≥5s 连续改善段计为一次有效响应 | 干预记录 + 逐帧状态 |

**冲动判定口径**：决策时刻处于 `stress / anxiety / distracted / fatigue / drowsy` 五态之一即记为冲动（与引擎 `IMPULSIVE_STATES` 一致）。

**一处方法学自纠（可主动讲）**：方案 v1.0 写"总决策数为 0 时冷静度记 1.0"，v1.1 改为 **缺失（None）**——
把"整轮没下单"当成"最冷静"会把组均值往上拉。同一结论在两个月后由前端独立修正（零样本显示「—」而非 1.00），
两条线各自收敛到同一个正确答案，是这套口径可信的一个侧面证据。

实验设计：自身对照（有反馈 / 无反馈两轮），同一受试者、同一价格序列（固定种子可复现），盲法控制条件名不下发。

### 2.6 组长主干 · 状态引擎（核心，全部自研）

| 层 | 实现方式 |
|---|---|
| **特征** | 8 频段 → 派生 R_tb(θ/β)、R_ba(β/(α+θ))、TAR(θ/α)、A_rel(α 相对基线增量)、still(陀螺仪 30s 均值)、RMSSD₆₀；全部在 **10s 滑动窗**上算，不是逐帧 |
| **伪迹三层** | ①单频段 15× 比值门（双向）；②肌电门 β+γ 同升（默认关，见 §4.3）；③接触门 `poorSignalLevel ≥ 200` 直接丢 |
| **z 门控** | 8 态各自一组合取条件；阈值来自映射表方向 + 经验初值，逐人校准 |
| **时间确认** | 5s 窗、命中率 ≥60%，**按时长不按帧数**（1 Hz 与 8 Hz 下等价） |
| **仲裁** | 优先级 + 置信度 `0.6 + 0.35·sep·strength`；`sep` = 与第二名的差距 |
| **校准** | A 闭眼 30s（δ 基线）→ B 睁眼 120s（全部 z 基线 + θ_ref）→ C **闭眼**放松 120s（放松锚点）；快速模式 15/40/40 |
| **双引擎** | Python（权威）+ JS（界面实时）逐帧对齐，**57 项常量 + 5 道闸门**，真实数据轨迹 **172/172** 一致 |
| **I_f 疲劳积分** | 触发 300s、半衰期 600s、断帧上限 120s；只动计数器不改判据 |

**三个"改过才成立"的设计**（都有实测支撑）：

1. **θ_ref 必须取 B 段**。取 A 段会让 `θ_norm` 恒 <1 → 疲劳积分永不累积 → 校准后疲劳永远判不出来。
2. **C 段必须闭眼**。实测闭眼 α 是睁眼的 **3.4 倍**（A 段 77.6k vs B 段 22.9k）；原型漏了"闭眼"两字，
   补测后 `c_anchor_z` 才从不可用变为达标。
3. **校准估计量必须与运行时同尺**。原先校准用逐帧特征估 μ/σ、运行时用 10s 窗均值，σ 差 **2.3–3.4 倍**，
   等于判据灵敏度被悄悄压掉 2–3 倍（D2_B 的 122 帧里 focus 判 0 帧）。v3.16 统一为窗口估计量后，`c_anchor_z` 由 3.42 → **12.49**。

## 三、数据来源（严格分类）

> **一句话先说清**：本项目**没有使用任何公开数据集**做训练或验证。
> 数据只有两类 —— 自己采的真机数据、自己生成的合成数据；判据依据是公开文献。

### 3.1 类型一：判据依据 —— 26 条 VERIFIED 文献

按状态列出**真正驱动判据**的那几篇（完整 26 条见 `阶段一交付包_20261013/附件2 阅读卡总表`）：

| 状态 | 判据 | 主要文献依据 | 证据强度 |
|---|---|---|---|
| **stress** | `z(RMSSD₆₀) < −1.5` | Laborde et al. 2022（Meta 223 项研究：慢呼吸升迷走 HRV）；Goessl et al. 2017（Meta 24 研究/484 人，HRV 生物反馈减压 g=0.83）；Zou et al. 2018（Meta 17 RCT：HFn g=+0.37、压力 g=−0.80）；Engert et al. 2016（TSST 压力期 HF-HRV 抑制、恢复期回升，N=114） | **Ⅰ**（最强维度） |
| **relaxed** | `z(A_rel) > +1.5`（α 相对基线升高） | Cahn & Polich 2006（冥想→α↑）；Park 2026（闭眼后区 α 相对功率↑，d=1.553）；Lomas et al. 2015（56 篇/1715 人，α+θ 共升）；Kawashima 2024（α↔副交感 nHF 正相关，N=15） | Ⅰ / Ⅲ |
| **focus** | `z(R_tb) < −1.0` + RMSSD 不低 + 体动平静 | Ismail & Karwowski 2020（β/(θ+α) engagement index 与任务负载正相关）；Morillas-Romero 2015（θ/β 比↔注意定向，N=110）；Klimesch 2012（α↓=去同步=注意投入） | Ⅰ |
| **distracted** | `z(R_tb) > +1.0` | 同上（R_tb 的两端）；Gkintoni & Halkiopoulos 2025（θ/β 为稳健认知负荷指标） | Ⅰ |
| **drowsy** | `z(TAR) > +1.5` 且 `z(δ) > +1.0` | Tran et al. 2020（Meta：精神疲劳 θ 增幅最大 g=1.03）；Zhang 2018（嗜睡驾驶→δ↑ 且 θ/α↓）；Lal & Craig 2002（驾驶疲劳→δ、θ 显著升）；Borbély 1982/2016（δ=睡眠稳态标志） | Ⅰ / Ⅱ |
| **fatigue** | `z(R_ba) < −1.0` 且 `I_f ≥ 300s` | Wascher 2014（额区 θ 随任务时程线性上升）；Boksem 2005（3h 任务→θ↑、目标导向注意受损）；Craig 2012（疲劳→全皮层 θ↑）；Snipes 2022（睡眠剥夺同样升内侧前额 θ） | Ⅱ / Ⅲ |
| **anxiety** | `att < 40` 且 `med < 40` | ⚠️ **无独立效度文献**：用的是设备厂商 eSense 指数的既有定义（黑盒），仅作工程口径 | **工程口径** |
| **flow** | `att/med > 60` + 稳定 5 帧 + `sync` 达标 | ⚠️ **`sync` 为本实现派生指标，官方无此字段**；无直接文献阈值 | **工程口径** |
| 金融场景 | 行为层不判脑波 | Gehring & Willoughby 2002（损失诱发更大 FRN、损失后更冒险）；Tripathi & Sharma 2023（模拟交易情绪分类 85.65%/85.05%）；Kwak & Grable 2025（N=10：脑波不直接预测单次冒险） | Ⅱ / Ⅲ |

**两条必须主动交底的边界**：
- `anxiety` / `flow` 是**工程派生口径**，不宜说"诊断出"，只能说"与该状态一致的模式"；
- 金融直接实证只有 3 篇、其中 1 篇是 N=10 的**反面**小样本 —— 所以本项目**不外推投资建议**。

**为什么 DEAP 出现在文献里却不是数据来源**：DEAP（Koelstra et al. 2012，32 人 × 40 段视频情绪诱发，
32 通道 EEG + 8 路外周）在本项目里只作**范式参照**与"额区 α 效价 75–85%"结论的出处；
它是多通道湿电极，与单通道干电极不可直接迁移。综述里也明确写了"公开数据集本轮仍沿用 DEAP"属文献层面，
**项目自身未下载、未训练、未验证任何公开数据集**。

### 3.4 数据质量的关键实证（都是本次实测，可直接进 PPT）

| 验证 | 数据 | 结论 |
|---|---|---|
| **V2 δ 可测性**（A 闭眼 vs B 睁眼） | δ 中位 27.0k vs 20.3k（**1.33×**）；α 中位 77.6k vs 22.9k（**3.4×**）；θ/α 0.32 vs 0.91 | 闭眼 α 增强在单通道额区**可复现**，是 `relaxed` 判据的实证基础；也是"C 段必须闭眼"的原因 |
| **V4 说话肌电**（静默 vs 说话） | δ 13.1k → **122.9k（9.4×）**；θ 16.7k → 44.7k（2.7×）；α 1.7×；**β 26.3k → 31.5k（仅 1.2×）** | 说话伪迹走**低频位移**通道，β+γ 肌电门无效（拦截率 10%）→ 肌电门保持关闭，改用协议约束"任务期间不发声" |
| **V3 signal 档位** | 1876 帧：`P50=0`、`P90=0`、`P99=26`、`max=27`；**100% 帧 <200**，98.3% 为 0（最佳接触），仅 1.7% 落在 26–27（"一般"） | `signal` 门限 200 有效，无"未接触却参与判别"的帧；真机接触质量稳定 |
| 伪迹率 | 校准段 5.4% | 15× 阈值在真机定标下合理 |

> V4 那行是本项目最值得讲的一条实证：**文献里"肌电伪迹看 β+γ"的常规做法，在说话场景下失效**。
> 不是没想到，是做了才发现方向错了 —— 所以改用低频 δ + 协议约束。

### 4.2 存在的问题（按影响分级）

#### P1 · 会影响"能证明什么"，但已如实标注

| 问题 | 影响 | 现状 |
|---|---|---|
| **只有 1 名受试者**（sub01） | 无法谈跨被试泛化；所有阈值仍是经验初值 | 已在 PPT 大纲 P12、README §8 明示 |
| **无金标准标签** | 不能算准确率；"8 段主判"只是分布描述，不是正确率 | 全部文档统一口径：不宣称准确率 |
| **本机无 RR 通道** | `stress` 真机恒不可判；`RMSSD`/`HR` 不可算 | 界面三处标「无 RR」；校准判据已拆 `hrv_ok` |
| **`anxiety`/`flow` 是工程口径** | 不能与 A 档状态同等表述 | README §8.1 分 A/B/C 三档写明 |

#### P2 · 判据设计层面（已知未改，改了会动已验收结果）

| 问题 | 数据 | 为什么不改 |
|---|---|---|
| **疲劳与分心/放松结构性共现** | `R_ba=β/(α+θ)` 要低只能 β↓ 或 α↑，而 β↓ 必然抬 `R_tb`（分心门控）、α↑ 必然抬 `A_rel`（放松门控）→ 三态共现稀释 `sep`。实测：I_f 刚达标时 conf **0.61–0.67**（弱判别，只记录）；随 I_f 继续累积升到 **0.70–0.76** 才弹 mild | 改 `conf` 会同时改对拍闸门第 3 列与 8 段主判率，属设计决策 |
| **`flow` 的 `sync` 要求与"稳定于高值"矛盾** | att/med 完全恒定时差分为 0 → `sync` 无定义 → flow 判不出（实测恒值 75 → neutral；正弦同向 → flow 0.95） | 同上 |
| **`neutral` 占约 25%** | 门控全为合取，不确定即判 neutral | 这是"不打扰"的刻意取舍，已写进口径 |
| **长断流后单帧可通过时间确认** | 30s 断流 + 1 帧 relaxed → 直接确认（30s 被算作该状态持续） | 属边界缺陷，未影响现有数据 |

#### P2 · 工程层面（不影响功能）

| 问题 | 说明 |
|---|---|
| `app.js` 仍是单体（2311 行） | 已拆出 `util.js`(60) 与 `chart.js`(189)；`calibration/reminders/settings` 三块待拆 |
| `state_engine.py` 的 calibration mixin 未拆 | 已拆出 `mockdata.py`(150)；re-export 保持 13 个脚本兼容 |
| 日志未统一时间戳 | 90 处 `print`，收益低、改动面大，暂缓 |

#### P3 · 演示层面（已写进脚本规避）

| 问题 | 处置 |
|---|---|
| 点「压力」需等 8–10 秒（HRV 60s 窗未换完） | 脚本要求提前预告 |
| 点「疲劳」结果不稳定 | 手动注入时 I_f 未预置，常先判成 distracted 0.95；要不要判 fatigue 取决于此前累积的 I_f。演示疲劳改用**自动轮播到疲劳相位**（有 I_f 预置，实测判 fatigue 并弹 mild） |
| 自动轮播 10 分钟仅 7 次提醒、前 88 秒无提醒 | 脚本禁用"等提醒"，改为主动点格子 |

### 4.3 一个必须说清的取舍：肌电门为什么关着

`ARTIFACT_EMG_GATE=False` 不是没做，是**做了并且验证了不适用**：
V4 实测说话时 δ 升 9.4×、β 仅 1.2× → 伪迹走低频位移而非肌电高频，β+γ 门拦截率仅 10%。
代价是说话段的 TAR/δ 会升高（v3.16 后 V4_TALK 更明显落到 drowsy），因此**协议上要求任务期间不发声**，
而不是靠算法"猜"掉它。

## 六、答辩口径速查（被问到就照这个说）

| 提问 | 回答 |
|---|---|
| 判据有科学依据吗？ | 分三档。`stress` 有 HRV 文献阈值（Laborde 2022 等 Meta）；`drowsy/relaxed/focus/distracted` 是共识 + 工程门控；`anxiety/fatigue/flow` 是工程派生口径，只说"与该状态一致的模式" |
| 准确率多少？ | 不宣称。没有金标准标签，任何数字都是假的。宣称的是链路通、判据可复现、双引擎逐帧一致（172/172） |
| 数据从哪来？ | **自采**：1 名受试者、5 份 dump、1876 帧，五段协议自己采的。**未使用任何公开数据集**；DEAP 只作文献范式参照 |
| 为什么不用深度学习？ | 单通道 + 单被试 + 无标签。深度模型既无法验证也不会比明确判据更可信；先要可解释、可复现 |
| 8 态都能判吗？ | 都能，但证据强度不同（A/B/C 三档）。另外 neutral 约占 25%，这是"不打扰"的代价 |
| 为什么有些格子是灰的？ | 压力依赖 HRV，本机硬质头环无 PPG，`stress` 恒不可判。界面直接标「无 RR」，不装作在等 |
| 疲劳为什么有时不提醒？ | 疲劳的置信度随 I_f 累积上升：刚达标时 0.61–0.67（弱判别，只记录），继续累积到 0.70–0.76 才弹 mild。这是"证据够了才打扰"，不是漏报 |
| 两个引擎怎么保证一致？ | 57 项常量 + 5 道闸门（常量/逐帧轨迹/校准基线/字段契约/真实数据 172-172） |
| 讲一个"测试骗过你们"的例子 | 三个：①疲劳测试只在极端 θ 上通过，回到现实区间判不出；②θ_ref 取 A 段导致校准后疲劳永不可达；③校准 σ 用逐帧、运行时用窗均值，灵敏度被压 2–3 倍而所有测试都绿 |
