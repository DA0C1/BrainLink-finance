# 全项目共用数字（v3.16，2026-11-11）

> 文档里要写数字，先来这里对一遍。改实现导致数字变化时，**先改本文件**，再改引用处。

## 一、产品口径

| 项 | 值 |
|---|---|
| 判别状态 | **8 态**：stress / anxiety / drowsy / fatigue / distracted / flow / focus / relaxed（+ neutral） |
| 主界面核心指标 | **6 项**：att/med、R_tb、RMSSD₆₀、HR、I_f、电极接触 |
| 提醒级别 | **4 级**：silent / mild / calm / strong（strong 由同状态 600s 内第 3 次 calm 升级） |
| 响应式断点 | **15 档实测**（1920×1080 … 320×568），见视觉设计系统 §八 |
| 校准协议 | 快速 **15/40/40s**（95 帧）；完整 **30/120/120s**（270 帧）；1 帧 = 1s |
| 数据源 | mock / replay(CSV) / serial(TGAM) / paste(JSONL) |
| 包内演示数据 | `项目文件/data/demo_mock_8phase.csv`（**合成**，520 行 / 10.4 分钟；含 `demo_` 前缀白名单，真机数据仍排除） |
| 前端依赖 | 零第三方；纯 `<script>`，断网可用 |
| Python 依赖 | 标准库 + pyserial（真机串口）；Pillow 仅素材后处理 |

## 二、引擎关键常量

| 项 | 值 |
|---|---|
| 窗口 | EEG 10s / HRV 60s / GYRO 30s |
| 伪迹 | 单频段 15×；R_tb 15×；肌电门默认关闭 |
| 接触 | `poorSignalLevel ≥ 200` 判接触无效 |
| 时间确认 | 5s 窗、命中率 ≥60%（按**时长**） |
| 置信度 | `0.6 + 0.35·sep·strength`；弱判别阈值 0.7 |
| I_f | 触发 300s、半衰期 600s、断帧上限 120s |
| 校准估计量 | **window10**：band 派生特征用 10s 窗均值估 μ/σ（v3.16 起） |

## 三、真机数据（当前唯一受试者 sub01）

| 项 | 值 |
|---|---|
| 有效 dump | 5 份 / **1876 帧**（2026-11-09 四份 + 11-10 补测一份） |
| 字段完整性 | 缺字段 0、频段零值 0、负值 0 |
| signal 分布 | 0:1844 / 26:31 / 27:1（均 <200，正常参与判别） |
| RR / 心率 / 陀螺仪 | 纯 Python 解析器路径下**不存在**（协议边界） |
| 校准（D2 A/B/C） | A/B/C = 32/122/122 帧；clean 29/114/118；伪迹 5.4%；接触 0% |
| θ_ref | 20229.0（来源 B） |
| c_anchor_z | **12.49**（v3.16 window10；旧逐帧估计量为 3.42，已作废） |
| 8 段主判（v3.16） | D2_B neutral 92 / distracted 12 / drowsy 9；D2_C relaxed 79 / focus 22 / neutral 19；V4_TALK drowsy 24 / distracted 11 / neutral 5 |

> v3.16 换了校准估计量后，D2_C 出现 focus、V4_TALK 落到 drowsy。前者是放松段
> `task_active=True` 下 focus 门控更容易满足；后者是朗读 δ 升 9.4×（V4 实测）被
> TAR/δ 当成嗜睡。两者都是"灵敏度提高后暴露的已知口径问题"，不是随机波动。
> 答辩时按 README §8.3 说明；不要把 V4_TALK 的 drowsy 当作真实困倦。
