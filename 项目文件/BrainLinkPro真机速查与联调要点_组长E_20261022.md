## 二、首次使用流程（5 步）
1. **充电**：取下核心模块（撬起 ≤30°，勿弯折柔性电极排线），USB 充电至红灯熄灭
2. **组装**：硬头环——以 30° 角将核心模块插入传感器支架 USB 口，回正按压卡紧；软头环——数据接口 B 对准 A 插入并卡入卡扣槽（**软头环须先组装再开机，否则心率/额温传感器不可用**）
3. **开机**：核心模块**水平放置**，长按 LOGO 按键至 2 次震动（红蓝灯交替闪烁）；短按关机（1 次震动）
4. **佩戴**：由上往下戴，硬头环眉上 2-3cm，2 金属触点紧贴前额（避免头发/汗液遮挡），耳夹夹**左**耳垂；软头环心率绿灯+3 金属点贴前额、模块位于左耳上方；**佩戴正确约 1s 后两次短振动确认**
5. **连接确认**：开手机蓝牙 → 开机 → 清理后台 → 打开 App → 右上角信号图标变"绿色正常"再开始采集（切换 App 前先清理后台，防蓝牙通道占用）

## 三、信号质量图标（四档，对应阶段 B「signal 档位标定」）
| 图标 | 含义 | 处置 |
|---|---|---|
| 1 | 未连接蓝牙 | 重开核心模块/手机蓝牙 |
| 2 | 已连接但未检测到脑波 | 检查佩戴（电极未贴肤） |
| 3 | 已连接但信号不稳定 | 电极接触不良（头发/汗液遮挡）→ 重新贴合 |
| 4 | 佩戴正确，工作正常 | 开始正式采集 |

> **⚠ 四档图标 ≠ 数值口径（2026-10-23 补）**：透传给 SDK 的 `signal` 是 TGAM **poorSignalLevel**，
> 语义为 **0 = 信号最好，200 = 电极未接触皮肤，数值越大越差**
> （NeuroSky《MindSet Communications Protocol》：*The higher the number, the more noise is detected.
> A value of 200 ... contacts are not touching the user's skin*）。
> 上表四档图标是 App 层的视觉映射，**不能当作数值阈值用**。项目里曾把方向写反（`signal>=200` 判"良好"），
> 已修正，见清单 §1.4。

## 三之二、Windows 蓝牙配对的坑（官方 FAQ）
1. 配对时蓝牙列表可能出现**两个同名设备** → 选名字前**带耳机图标**的那个
2. 配对成功后系统会生成**两个虚拟 COM 口**（一进一出）→ **必须选「传出 / 输出」**那个
3. 选错的表现极具欺骗性：**端口能打开、不报错，但永远 read 不到数据**
4. 分辨：蓝牙设置 → 更多蓝牙选项 → COM 端口，看哪个标着"传出"
5. 波特率 **115200**（官方 sample `CushySerial(..., 115200)`）。注意这是**蓝牙 SPP 链路速率**，
   不是 TGAM 芯片 UART 的原生 57600

## 四、与项目引擎/任务4 的映射要点
| 说明书事实 | 项目落点 |
|---|---|
| 心率传感器（PPG 绿灯）仅软头环可用，须先组装再开机 | HR 特征依赖软头环；`SdkAdapter.onExtendEEG` 的 heart 直读即 PPG；RR 间期从 onRR 回调（3 个间期/次）灌入 HRV 缓冲 |
| 信号质量四档图标 | 阶段 B「signal 标定」前置：档位不稳定则 RR/δ 数据可信度先打折，按通过标准（稳定 ≥3 档占比 >80%）决定数据丢弃策略 |
| 电极 GND/REF（干电极易受头发/汗液/动作影响） | 伪迹门（8× 单频段 / 15× R_tb）与"说话肌电/佩戴动作"验证项的物理依据；佩戴规范写入受试者指导语 |
| 正确佩戴 1s 后两次震动 | 可作"开始采集"的统一信号；真机流程在震动后再启动 session |
| FAQ：只能分析生理状态，**无法解析思想与记忆**；纯接收不向大脑发送 | 答辩伦理口径（隐私/安全）现成依据 |
| 连续使用 ~4h | 一次实验（2 轮 ×10-15min + 校准）电量余量充足；单次佩戴上限 ~30-40min，多受试者需充电轮换 |
| UART 115200 / TGAM | 若需绕过蓝牙直读串口（厂商协议），波特率 115200 为关键参数；默认走官方 BrainLinkParser-Python SDK（onEEG/onExtendEEG/onGyro/onRR 四回调） |
| Python SDK 只有 `parse()`，**没有 `setDataType()`** | Android 侧靠 `setDataType(mac, DATATYPE_...)` 主动开启数据输出；Python 侧无法下发 → **设备默认是否推 RR/心率未知**，必须实测确认。这是"装了官方 pyd 就一定有 HRV"不成立的原因 |
| Android `onRR(mac, ArrayList rr, int oxygen)` | RR 是**变长列表**还带**血氧**，与 TGAM 定长段机制完全不同 → 证明 RR 属 BrainLink 私有包，**不在 TGAM 标准帧内**，纯 Python 解不出来 |
| 纯 Python 自解析已就绪 | `项目文件/tgam_parser.py`：TGAM 标准帧全覆盖（signal/eSense/8 频段/raw），无 RR/心率/gyro；两 bridge 已内置自动降级。影响量化见 `纯Python自解析可行性评估_组长E_20261023.md` |
