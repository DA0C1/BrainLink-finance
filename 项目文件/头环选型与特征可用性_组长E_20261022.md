# 头环选型、双头环适配与场景区分（组长 E，2026-10-22）

> 背景：真机 BrainLink Pro 随附**软、硬两款头环**，传感器与用途不同。本文基于官方资料（Macrotellect Quick Start 手册 / 官网 / NeuroSky KB / arXiv 佐证）+ 引擎 v2.8.6+ 门控代码逐行核实，给出**具体差异、双头环功能适配方案、分场景区分**。依据出处见文末。

## 一、两款头环的具体差异（官方口径）

**官方 Quick Start 手册原文**（ManualsLib 存档，与真机说明书同源）：
> "The soft headband contains **additional heart rate and frontal temperature sensors**, comfortable and suitable for **long time wearing**; the hard headband integrates **EmoLight band and ear clip electrode**, which can **change color according to the brain state** and provide **more sensitive EEG data**, suitable for **short time high sensitivity EEG acquisition**."

| 维度 | 软头环 | 硬头环 |
|---|---|---|
| 附加传感器 | **PPG 心率（绿光）+ 额温** | **EmoLight 灯带**（随脑波变色） |
| EEG 表现 | 标准 | **更灵敏**（佩戴更贴合，短时高灵敏度采集） |
| 佩戴 | 柔软舒适，适合**长时间** | 3 段式头箍（PC/TPU），适配头围 48–60cm，接触更稳 |
| 反馈 | 无灯带 | 灯带实时可视化脑状态 |
| 耳夹电极 | 有（REF+GND 双传感器，夹左耳垂） | 有（REF+GND 双传感器，夹左耳垂） |
| 适用 | 长时间佩戴、需心率/体温特征 | 短时精细 EEG 采集、神经反馈演示 |

- 心率 PPG **只在软头环**且须**先组装（软头带+核心模块）再开机**方可用（说明书）
- 两环均有耳夹电极（REF+GND，官方 FAQ：前额两触点 + 耳夹"感测回路"）
- 官方 FAQ 伦理口径：仅感知生理状态，不泄漏具体思维信息（答辩背书可用）

## 二、引擎特征依赖与可用性矩阵（state_engine.py v2.8.6+，逐行核实）

| 状态 | 主判据 | 依赖 HRV？ | 软头环 | 硬头环 |
|---|---|---|---|---|
| focus 专注 | θ/β 主口径 + 排除法（RMSSD 缺失放行 L377） | 弱 | ✅ | ✅（EEG 更灵敏或更稳） |
| distracted 分心 | θ/β + A_rel 等 | 否 | ✅ | ✅ |
| relaxed 放松 | A_rel + RMSSD(+0.7 权重 L630) | 部分 | ✅ | ⚠️ 可判但弱化（权重落空 L427） |
| stress 压力 | **z(RMSSD)<−1.5（L386，无缺失放行）** | **主判据** | ✅ | ❌ **不可判** |
| anxiety 焦虑 | att/med 双低 + z | 否 | ✅ | ✅ |
| flow 心流 | att/med 双高 + 派生同步率 | 否 | ✅ | ✅ |
| fatigue 疲劳 | θ_norm 积分 + 排除应激（RMSSD 缺失放行 L405） | 部分 | ✅ | ⚠️ 可判但排除应激失效（放宽） |
| drowsy 嗜睡 | TAR + δ 合取 | 否 | ✅ | ✅ |

## 三、双头环功能适配方案

**结论：无需改引擎代码即可双环适配**——缺失路径已隐式安全（机制精确化，state_engine.py L454-457：**门控不过或关键特征 nan → 该状态 score 置 -inf，不参与仲裁**；stress 门控 L386 无 isfinite 放行 → 永假不误报；focus/fatigue 缺失放行；评分项 A_rel/still/RMSSD_60/delta 缺失置 0 有 isfinite 保护，stress 评分 L430 无保护但由 -inf 兜底）。适配落在**数据层与声明层**：

| 层 | 适配动作 | 状态 |
|---|---|---|
| 数据层 | 录制器 CSV 增加 `headband` 字段（soft/hard），逐帧或按段记录 | 任务4 交付时补齐（组长代改） |
| SDK 层 | SdkAdapter 已把 heart/RR 与 EEG 解耦——软环走 HR/RR 通道，硬环自动缺失 | ✅ 已完成，零改动 |
| 引擎层 | 可选增强（真机数据到手后，不臆造参数）：`mode` 开关输出 `available_states` 声明（soft=8 态 / hard=7 态无 stress），供日志/UI 标注 | 预留接口，待真机验证 |
| 校准层 | 基线采集按头环类型分别建立（硬环基线不含 HR/RMSSD 项） | 阶段 B 执行 |
| 参数层 | 硬环 EEG 更灵敏 → 伪迹门/σ 是否微调**待真机数据对比后定**（不预设） | 阶段 B |

## 四、分场景区分（实验与演示配置建议）

| 场景 | 头环 | 理由 |
|---|---|---|
| **正式金融盯盘实验（受试者，主实验）** | **软头环** | 8 态全量；理智度三指标需 stress/放松/疲劳；V1 RR 质量、V5 咖啡因依赖 PPG |
| **EEG 精细专项（δ 可测性 V2、肌电 V4）** | **硬头环** | EEG 更灵敏，闭眼/睁眼 δ 区分、β/γ 肌电对比更明显 |
| 演示 / 体验 / 神经反馈展示 | 硬头环 | EmoLight 灯带实时可视化，无 HRV 需求 |
| 长时间佩戴 / 户外 / 多特征采集 | 软头环 | 舒适 + 心率/额温 |
| 硬头环跑主实验 | ❌ 不建议 | stress 不可判，理智度指标失真（除非答辩披露降级） |

## 五、答辩口径

- 主实验：软头环全量 8 态；硬头环用于 EEG 专项与灯带反馈
- 硬头环下 stress 不可判 = **预期降级**（非缺陷），披露即可；引擎缺失路径已防误报
- 官方 FAQ 伦理口径作背书（只能分析生理状态、纯接收不发送）

## 八、数据口径与判断机制复用性（关键 Q&A）

### 8.1 分场景使用可行吗？
**可行**。核心模块为**同一块**（官方手册：attach the core module to the base of the headband，两环互换），换环=换头带+重佩戴+重校准。**分场景=分实验段**：一次佩戴只用一个环，段间换环；录制器按段记录 `headband` 字段。**不建议同一实验段内中途换环**——HRV 通道中断、基线切换会污染判别（对比实验除外，须在日志标注）。

### 8.2 不同头环的数据口径相同吗？
| 通道 | 口径 | 说明 |
|---|---|---|
| EEG 8 频段 / eSense / 陀螺仪 | **相同** | 同 TGAM 核心模块、同帧格式；onEEG/onExtendEEG/onGyro 字段一致 |
| HR / RR→RMSSD | **仅软环** | 硬环该通道缺失（SDK 回调无值） |
| 信号质量/绝对幅值 | 可能微差 | 硬环"more sensitive"=佩戴贴合/接触阻抗优势，非标定差异；由个体 z-score 基线吸收 |

### 8.3 能用同一套判断机制吗？
**能，判据同源，无需改引擎**（θ/β 主口径 + z-score 归一化天然吸收佩戴差异）。三条约束：
1. **基线按环分列**：校准协议（§六）为 soft/hard 各建一套基线（硬环基线不含 HR/RMSSD 项）
2. **硬环状态集收敛**：7 态可用（stress 不可判=预期降级），relaxed/fatigue 弱化
3. **可选 mode 声明**（真机数据验证后）：引擎输出 `available_states`（soft=8 态 / hard=7 态无 stress），仅声明层增强可解释性，不臆造参数
